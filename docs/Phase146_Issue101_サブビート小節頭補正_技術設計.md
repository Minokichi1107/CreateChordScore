# Phase146 / Issue #101 — サブビート位置を小節頭にする技術設計（実装・監査中）

- 状態: 基本実装済み。PR #166 の追加修正・回帰確認中。マージ前の最終監査とCI確認は未完了
- 対象ブランチ: `phase146/issue-101-local-anchor-slot-width`
- 関連: [Issue #101](https://github.com/Minokichi1107/CreateChordScore/issues/101)、[PR #166](https://github.com/Minokichi1107/CreateChordScore/pull/166)、[Issue #130](https://github.com/Minokichi1107/CreateChordScore/issues/130)

## 1. 目的と範囲

Issue #101 の要件は、ユーザーが指定した位置を小節頭にし、その位置を新しい小節の先頭スロットとして扱うこと。指定位置より前の奇数拍側の空スロットを、新しい小節の先頭に残してはならない。

今回の設計では、既存の8分グリッド（1拍を2スロットに分けるグリッド）を基準に、拍の前半・後半のどちらも補正位置として表せるようにする。

### Product Intent（製品意図）

- PI-01: 8分音符の裏拍（「&」）を正確な小節頭として指定できる。
- PI-02: 局所補正は指定位置以降の小節頭を再構築し、前方の小節境界を原則維持する。
- PI-03: 全曲補正は局所補正と別操作として、曲全体の小節頭を指定位置基準で再構築する。
- PI-04: 将来のセクション単位補正に備え、補正アンカーと補正範囲を分離する。セクション補正自体は今回実装しない。
- PI-05: コードの時刻、表示位置、編集、再生カーソル、シーク、小節境界を整合させる。

## 2. 現状の事実と主なリスク

調査対象は PR #166 のブランチ上の `js/timing.js`、`js/chartmode.js` および既存の `scripts/test-phase146-timing.mjs`。

1. `buildGridViewModel()` は `createTimingModel()` に `resolutionPerBeat: 2` を渡す経路を持ち、編集グリッドは原則として1拍あたり2スロットである。
2. `_getBeatTimeFromSlot()` はクリックされたスロット番号を拍番号に丸めるため、拍の後半をクリックしても拍頭の時刻しか返さない。
3. `applyAnchorRepair()` と `applyWholeSongRepair()` は現在、`beats[]` 上の時刻をアンカーとして小節頭を構築する。
4. `quantizeTime()` は小節頭が `beats[]` の要素と一致することを前提に、小節内の拍位置を求める。一致しない場合は `beatInMeasure = 0` のまま進む可能性がある。
5. 通常表示の Continuous projection（連続表示への投影）と Slot-based projection（スロット単位の投影）は別経路を持つ。境界の意味を各経路に個別実装すると、表示と編集が食い違うリスクがある。
6. `_getExactTimeFromSlot()` はサブビート時刻を返せるが、小節内の表示スロット比率から線形補間する関数であり、補正アンカーの権威ある変換関数としてそのまま流用できるとはまだ確認できていない。

## 3. 推奨する設計原則

### 3.1 アンカー位置を「拍インデックス＋拍内分割位置」で表す

設計候補:

- `beatTime`: 元の `beats[]` 上の拍頭時刻
- `subdivision`: 1拍内の分割位置。現行グリッドでは `0` = 拍頭、`1` = 拍の後半（「&」）

この表現は時刻そのものだけを丸めて保存するよりも、クリックされたグリッド位置を保持しやすい。フィールド名や保存形式は実装前に既存 `repairRule` の互換性を確認して確定する。

アンカーの実時刻は、拍頭インデックスと `resolutionPerBeat` からグローバルスロット位置を求め、そのスロットの時刻を共通のスロット時刻配列から取得する。概念上は次のとおり。

```text
globalSlotIndex = beatIndex * resolutionPerBeat + subdivision
anchorTime = slotTimings[globalSlotIndex]
```

これにより、一定テンポを曲全体の前提にせず、隣り合う拍の間隔に基づく時刻を扱える。ただし、実際の `buildSlotTimings()` の境界条件、曲末尾、欠損拍への挙動を実装前にテストで確認する。

### 3.2 小節境界を raw beats のインデックスだけで表さない

サブビート位置を小節頭にする場合、その境界時刻は `beats[]` に存在しないことがある。したがって、境界を単に「raw beats 上の downbeat 時刻」として扱うモデルは不十分。

推奨案は、TimingModel 内で各小節の開始位置を共通グリッド上のスロット位置として保持し、`startTime` / `endTime` はそのスロット位置から導出すること。

- `measureStartSlotIndex`: 小節頭のグローバルスロット位置
- `measureEndSlotIndex`: 次の小節頭のグローバルスロット位置
- `startTime` / `endTime`: 対応するスロット時刻

これらは設計上の候補名であり、現行の公開APIへそのまま追加することを確定したものではない。既存の小節情報との互換性を検証してから最小限の内部表現を選ぶ。

### 3.3 局所補正と全曲補正は範囲の違いとして維持する

- 局所補正: アンカーより前の既存境界を維持し、アンカーを新しい境界として採用し、以後を小節幅ぶんのスロット間隔で再構築する。
- 全曲補正: 同じアンカー／スロット基準を使い、曲全体の境界を再構築する。
- 将来のセクション補正: アンカー位置とは別の `scope`（補正範囲）概念で表せるようにする。ただし今回の実装対象外。

重要: オフビートの時刻を人工的に `downbeats[]` に混ぜるだけの変更は避ける。下拍が raw beats にあるという既存前提が残ると、量子化側で不整合が再発するため。

## 4. 関数単位の変更方針

| 対象 | 方針 | 理由 |
|---|---|---|
| `buildSlotTimings()` | まず維持し、境界条件をテスト | 既存の拍内スロット時刻を再利用する |
| `_getBeatTimeFromSlot()` | 補正メニュー用にクリックした分割位置を失わない変換へ変更 | 現状は拍頭へ丸める |
| `applyAnchorRepair()` | アンカーをスロット位置として扱えるよう拡張 | 局所補正で拍の後半を指定可能にする |
| `applyWholeSongRepair()` | 同じアンカー表現を利用 | 局所補正と全曲補正で位置解釈を分岐させない |
| `buildMeasures()` またはその呼び出し境界 | 小節頭のグローバルスロット位置を保持できる設計へ拡張 | 小節頭が raw beats に存在しない場合を扱う |
| `quantizeTime()` | 小節頭の raw beat 一致検索への依存を解消 | 現在の silent fallback（無通知の代替処理）を避ける |
| `getContinuousMeasurePosition()` | 共通の小節境界を使うことを確認し、必要な場合のみ変更 | Continuous projection との整合性を保つ |
| `buildGridViewModel()` | 境界と表示メタデータの受け渡しを確認 | Slot projection への境界情報の一貫した伝達 |
| `_getExactTimeFromSlot()` | 既存の編集用途を維持。アンカー変換へ流用する場合は独立テスト | pickup時の逆変換に既知の制約がある |
| 再生・シーク関連 | 実装時に呼び出し経路を追跡して回帰テスト | PI-05の要件。現時点で無影響とは断定しない |

## 5. 量子化の不変条件

実装時に、少なくとも次の不変条件（invariant）をテストする。

1. 各小節の境界は共通のスロット時刻配列と対応する。
2. コード時刻を量子化した際、小節番号とスロット番号は同じ境界定義から算出される。
3. 小節頭が拍の後半にある場合、後半位置が新小節の slot 0 となり、直前の位置が新小節内の空 slot として残らない。
4. 局所補正ではアンカーより前の境界が意図せず移動しない。
5. 全曲補正ではアンカーを基準に全曲の境界が構築される。
6. 補正処理は raw `beats[]`、raw `downbeats[]`、コードの元時刻を破壊的に変更しない。
7. Continuous projection と Slot-based projection は同じ小節開始・終了時刻を参照する。
8. 境界がモデルの前提を満たさない場合、拍位置を黙って0にするのではなく、明示的に扱えるようにする。

## 6. テスト計画

### 単体テスト

- 4/4、`resolutionPerBeat = 2` で拍頭をアンカーにした場合、既存の境界と同じ結果になる。
- 同じ条件で拍の後半をアンカーにした場合、アンカー時刻が小節頭になり、次の小節頭は8スロット後になる。
- 不等間隔の beats を使い、固定テンポを仮定した時刻計算になっていないことを確認する。
- 曲頭・曲末尾・最後の拍に次拍がない場合の処理を確認する。
- 無効な拍時刻や範囲外アンカーを拒否／処理する規則を確認する。
- 局所補正、全曲補正、補正解除の各操作を独立して確認する。
- raw arrays が変更されないことを確認する。

### 統合・回帰テスト

- 通常表示と編集グリッドで小節境界が一致する。
- コードの表示位置と選択対象が一致する。
- コード追加・編集・貼り付け・衝突（collision）診断が既存の意味を維持する。
- 再生カーソル、クリック再生、シークが境界と一致する。
- PR #166 で確認済みの短縮小節の幅、後続小節の幅、短縮小節内の編集・再生位置が維持される。
- 弱起、beat-only、通常の最終行に対する既存挙動が変わらない。
- 6/8など未確定の拍子モデルを今回の変更で暗黙に解決したことにしない。

## 7. 実装順序

1. 現行 `buildSlotTimings()` と `quantizeTime()` のインデックス関係を、具体的なfixtureで固定する。
2. 補正アンカーをスロット位置として解釈する純関数を設計・テストする。
3. TimingModel が小節頭のグローバルスロット位置を保持できる最小の変更を行う。
4. 局所補正を対応させ、単体テストと既存Phase146テストを通す。
5. 全曲補正を同じアンカー表現に接続する。
6. Continuous projection、編集、再生・シークの統合テストを行う。
7. 問題がなければPR #166の範囲・Issue #101の受け入れ条件と照合する。

## 8. 実装上の決定事項と未解決事項

### 実装上の決定事項

- 補正アンカーは `beatTime + subdivision` で表す。`subdivision: 0` は拍頭、`subdivision: 1` は拍の後半（「&」）。
- アンカー時刻は `buildSlotTimings()` が生成する共通スロット時刻から取得する。
- 局所補正と全曲補正は同じアンカー表現を使い、補正範囲だけを変える。
- 全曲補正で先頭小節が「＆」境界で短縮され、かつ拍頭数が拍子の基準拍数に達する場合は、実際のスロット数を `displaySlotCount` に反映する。既存の弱起右寄せ経路が適用される先頭小節の表示は変更しない。
- `displaySlotCount` と `isWholeSongSubbeatTruncated` は実行時の派生値であり、保存しない。

### 未解決事項

- pickupを含む先頭小節での右クリック位置変換は近似であり、厳密な逆変換は未解決。
- `quantizeTime()` で小節頭がスロット時刻に一致しない場合、`beatInMeasure = 0` に黙ってフォールバックする既存リスクは未解決。
- 保存後の再読み込みを含む実サーバー経由の検証は別途必要。

既存の「確定事項」を変更したり、未確定のBeat / Measure / Slot定義やCollision（衝突）処理を先取りして確定したりしない。

## 9. 受け入れ条件

Issue #101 の最小受け入れ条件は、拍の後半を小節頭に設定したとき、その位置が新しい小節の先頭になり、前の拍の後半位置が新小節の先頭に空白として残らないこと。

ただし、コード表示・編集・再生・シークの整合性と既存機能の回帰テストが通るまでは、実装完了とはみなさない。
