## 1. 実現したこと（利用者から見た形）

```
右クリック
 ├ 📍 ここから先を小節頭にする   … ①（既存。名称のみ変更、動作は不変）
 └ 📍 曲全体をここ基準に組み直す … ②（新規）
解除: 🔄 小節補正を解除 → 元の小節構造に戻る
```

- ②は、指定した拍を小節頭にして曲全体を並べ直す。先頭に余った拍（1〜3拍）は短い小節として先頭に出て、**既存の弱起表示（空きスロット＋小節番号「0」）**で表示される。休符記号は出さない（仕様外）。
- 初回の範囲: **4/4・既存の拍のみ。**
- 4/4以外と `beat-only`（拍だけの解析）では、設定を拒否して理由をトーストで通知する（**仕様・期待動作。実画面では未確認** — 4章）。
- 1曲に補正は1つ。すでに補正がある曲では、置き換え確認ダイアログを出す。

## 2. 確定した設計（実装・マージ済み）

| 項目 | 内容 |
|---|---|
| 補正ルール | `{ version: 1, type: 'wholeSongDownbeat', beatTime }`。**この `type` 値が、現在の実装で使われる保存値**（Technical Design で確定し、マージ済み）。`raw.beats` / `raw.downbeats` は変更せず、補正は実行時に作る |
| 計算 | `idx` = `raw.beats` の0始まりの番号、`r = idx % 4`。新しい下拍 = （`r>0` なら `beats[0]`）＋ `beats[r], beats[r+4], …` |
| 同じ位相（r=0） | 元の小節構造と一致する |
| 先頭の短い小節の印 | `timing.js` が実行時に `measures[0].isLeading = true` を付与（保存しない）。`detectPickupMeasure()` が先頭でこの印を優先（閾値 0.75倍・±30% は不変） |
| 理由 | 既存の弱起判定は、1拍で94/101、2拍で90/102、3拍で50/100しか当たらず、印が必要だった |
| 触らなかったもの | `applyAnchorRepair()`（①）、`analysisLoader.js`、`server.py`、保存形式の検証処理 |
| 注意（CRLF） | `js/chartmode.js` は CRLF を維持する（`.gitattributes`） |

設計の詳細は `docs/issue129-technical-design.md`（PR #160 で正式配置。`type` の位置づけは本書と同じ表現に統一済み。「仮名」は「将来、名称を見直す余地がある」の意味）。
