## 目的と完了内容

Issue #101では、拍の後半（8分音符の裏拍、「&」）を小節頭の補正位置として指定した際、その位置が小節の先頭として表示・編集されることを目指した。

Phase146で対応したこと:
- 補正アンカーを拍頭だけでなく拍内分割位置（サブビート）でも扱えるようにした。
- 局所補正と全曲補正の両方でサブビートアンカーを扱う経路を整備した。
- 全曲補正で先頭小節が「&」位置から始まる場合、実際の表示スロット数を反映するようにした。
- このケースでは、弱起右寄せ変換（pickup projection：弱起位置への表示変換）による異なるスロット位置の衝突を避ける。
- 回帰テストを追加・拡張し、CIで実行した。

## 確定した設計・挙動

- **全曲補正と局所補正の表示差:** 全曲補正で先頭小節が「&」から始まる場合は実スロット数（1/3/5/7）で短縮表示する。一方、拍頭から始まる先頭小節は既存の弱起右寄せ経路を維持する。この非対称性は現行挙動として記録するが、両者を統一すべきかどうかは未決定。

- `beatTime + subdivision` で補正アンカーを扱う。`subdivision: 0` は拍頭、`subdivision: 1` は拍の後半（「&」）。
- アンカー時刻は既存の `buildSlotTimings()` が生成する共通スロット時刻から取得する。
- 局所補正と全曲補正は同じアンカー表現を使い、補正範囲を区別する。
- 全曲補正の短縮先頭小節では実際の表示幅を使う。4/4の確認ケースでは1・3・5・7スロット。
- この短縮先頭小節にはpickup projectionによる再マッピングを適用しない。異なるスロットが衝突してコードが隠れる可能性を避けるため。
- `displaySlotCount` と `isWholeSongSubbeatTruncated` は実行時の派生値であり、永続化しない。
- Beat / Measure / Slotの一般定義やCollision（衝突）全般の意味論は今回確定していない。

## 残課題・今回の範囲外

- **N-02:** `subdivision` の入力検証は未解決。範囲外の値は拒否される一方、非整数値は `0` に丸められ得る。
- **N-03:** 上書き確認ダイアログは `beatTime.toFixed(2)` の拍頭時刻だけを表示し、指定した「&」位置の時刻は表示しない。
- **N-04:** pickupを含む先頭小節での右クリック位置変換が近似である問題。
- **N-05:** `quantizeTime()` が小節頭と `beats[]` の一致を見つけられない場合、`beatInMeasure = 0` へ黙ってフォールバックし得るリスク。
- **N-06:** 曲末尾の最後の拍の「&」をアンカーにすると、末尾に不正な小節が生じ得る可能性がある。監査時点では、通常UIからこの位置を選択できないという説明は未再確認であり、UI上で選べないことを確定事実として扱わない。
- **互換性:** 旧アプリ版は `subdivision` を無視し、拍頭アンカーとして扱う可能性がある。旧版での再保存時に補正意図が失われるリスクに注意する。
- **内部API:** `pickNearestBeatInMeasure` など内部関数の戻り値・意味が変更されている。外部利用がないことを前提にせず、将来の呼び出し元変更時は再確認する。
- **短縮小節と弱起:** 全曲補正の「&」から始まる短縮先頭小節は、既存の弱起右寄せ表示とは異なる経路で表示され、現時点では弱起として扱われない。両者の表示方式を統一するかは未決定。
- 実サーバー経由の保存後再読み込み検証は、今回の受け入れ確認とは別途扱う。上記の「保存／再読み込み」は、今回実施したブラウザ上の受け入れ確認を指し、実サーバー経由の検証完了を意味しない。
- 6/8等の拍子モデル、Beat / Measure / Slotの一般定義、Collision処理全般の意味論は未確定。
