## 2. Risk Check — コードで確認した結果（リポジトリ読み取りのみ・無変更）

確認対象: `css/chart.css`、`js/chartmode.js`（`_resolveSectionMarkers` / `_buildSectionLayer` / `_renderChartGridContinuous` / `_applyContinuousChordLabelProjection`）。

### 2.1 行の構造（実コードから）
- 行 `.chart-row` = `display:flex; gap:4px; padding-right:16px`。小節 `.chart-measure` は枠1px・`overflow:hidden`。
- 小節の隙間は **4px**。行の左には `#chart-grid` の `padding:16px`（`overflow-y:auto`）がある。
- Layer は行に重ねる `position:absolute`。線は `.chart-section-cell`（枠1px透明）の内側%で置かれ、小節内側（`.continuous-track`）と同じ基準。
- コード `.continuous-chord` は `position:absolute; overflow:hidden`、背景なし。文字 `.chart-chord-name` は `left:2px; width:calc(100% - 4px)`、`white-space:nowrap; text-overflow:ellipsis`、左寄せ。
- Layer は小節より後に追加され、**文字より前面**に描かれる。

### 2.2 リスク #2（行の左端で −4px がはみ出す・切れるか）→ **問題なし（確認済み）**
- 行頭の小節の開始線（0%）は、小節の外枠から約3px左に出る。そこは `#chart-grid` の左 padding 16px の内側。
- `#chart-grid` の切り取り範囲は padding を含むので、**切れない**。横スクロールも増えない。
- 結論: 行頭での「0 に丸める」補正は**不要**。

### 2.3 リスク #3（4px 左へずらした線は何と重なるか）→ **場所で結果が違う（推測を訂正）**

| 開始位置 | 実際の線の位置 | 重なり |
|---|---|---|
| **小節頭**（実データ 79/104） | 小節の外枠から 3px 左〜1px 左。隙間（4px）の中 | **何とも重ならない**。前の小節の枠とも各1px空く。行頭の小節は左 padding の中 |
| **小節途中・最終拍**（実データ 15+10=25/104） | 前のコードのセグメントの**右端4pxの内側** | 前のコードの**文字ボックスの右端2pxと重なる**。ただし**文字そのものに触れるのは、その文字が自分のセグメント幅いっぱいまで伸びているとき**だけ |

訂正する点:
- 当初の推測「線が前コードの右端に乗る」は、**小節途中の開始のときだけ**正しい。小節頭では隙間に入るので乗らない。
- 当初の推測「長いコード名のときだけ重なる」は**不正確**。重なる条件は名前の長さではなく、**前のコードの幅（拍数と画面幅）に対する文字の長さ**。短い拍のコード・列数が多い・画面が狭い、のときに起きる。
- 重なっても、線は2px・コード文字は ellipsis で幅が決まっているため、**文字が隠れる最大は右端の約2px分**（レイアウトは壊れない）。
- 前のコードのセグメントが 4px より短いと、線はさらに前のコードへ入る。実データでの頻度は未確認（実装後の確認項目にする）。

追加で分かったこと（良い方向）:
- 小節頭の線が隙間に出ることで、**背景が小節色でなくステージ色**になる。silver で線が小節背景に埋もれる問題（コントラスト1.1〜1.4）は、小節頭の開始線については**改善する見込み**（数値は実装後に実測する）。
- 開始線の名前は線の子要素なので、線と一緒に4px左へ動く。名前の左端はコード左端から見て現状7px→3pxになる（4px近づく）。必要ならCSSで再調整する（§3）。

### 2.4 リスク #1（名前が入るかの判断と「px計測しない」原則）→ 方針確定
- ユーザー決定: **文字数からの推定（案b）**。正確な幅計測は要件にしない。
- 既存コードの事実: `_buildSectionLayer()` は行を `container.appendChild(rowEl)` する**前**に走るため、その時点では幅が取れない（clientWidth = 0）。一方、`_applyContinuousChordLabelProjection()` は全行を追加した**後**に、`measureEl.clientWidth` と測定用要素で幅を使う前例がある。
- 本設計の扱い: §4 を参照。

### 2.5 リスク #4（silver で四角が見えるか）
- 四角は小節の上端にあり、背景は小節色（silver ≈ `#6c6f77`、Section 色 `#00746B` 等）。線と同じく埋もれる可能性がある。
- 対策（設計に含める）: 四角に**ステージ色寄りの細い縁**（1px・明るい色）を付ける。実画面で見え方を確認し、不要なら外す。

### 2.6 リスク #5（四角と小節番号の干渉）— 今回の確認で新たに分かった点
- 小節番号 `.chart-measure-num` は小節の右上（`top:2px; right:4px`）。終了線が**小節の右端**（実データで多い形）にあると、7px の四角は番号の最後の桁に約0.5px触れる。
- 対策: 四角を **6px**（線の中心に水平で揃える）にする。番号との間が約1pxできる。実画面で確認する。

### 2.7 ChatGPT 依頼事項: 「4px 左でも実際の開始位置を誤認させないか」
- **データ・位置の意味は変わらない**。ずらすのは描画だけ（Projection の `chordId` / `edge` と `_resolveSectionMarkers()` の % は変更しない）。
- 見え方: 小節頭では「線が小節の入口の外」に出るので、**「この小節から」**と自然に読める。小節途中では線が前のコード側に4px食い込む。コード1つ分の幅（通常数十px）に比べて小さく、前のコードの最終部分と読まれる可能性は低いと判断するが、**実機で確認する**（受け入れ確認に含める）。
- 検証基準の更新: 設計書 Phase141 §3・§5・§10・§12.5 の「線 = セグメント左端 ±1px」は、**「左端 − 4px ±1px」**に読み替える（終了線は従来のまま）。

## 3. B — 開始線を4pxずらす

- 変更はCSSのみ。変数 `--chart-section-start-offset: 4px;` を `.chart-row` に追加（gap等と同じ階層）。
- 開始線: `transform: translateX(calc(-1 * var(--chart-section-start-offset)))`。`left:%` は変えない。
- 終了線の `translateX(-100%)` は変更しない。
- 開始線の名前（子要素）は線と一緒に動く。名前の `left` 値は「線の左端から 7px」を維持し、見た目は実機で確認して調整（調整はCSSのみ）。
- JS（`_resolveSectionMarkers` / `app.js` Projection）は**変更しない**。

## 4. A — 名前の置き場所（近似判断）

### 位置づけ（重要）
- 右に入るかの判断は、**配置を決めるための近似**。文字幅の正確な計測は要件ではない。
- 近似の誤差があっても、**最終手段の切り詰め（…）**で必ず収まり、表示は壊れない。
- 線の位置（%）は引き続き px 計測しない。この近似は**名前の置き場所を選ぶ**ためだけに使う。

### 判断（行ごと・開始線ごと）
```
推定幅   = 文字数 × 係数        （係数: 全角=1.0em 相当、半角=0.55em 相当 の目安。font-size 12px・太字）
右の余白 = 行の幅 × (1 − 線の位置)  − 余白
左の余白 = 行の幅 ×      線の位置   − 余白

推定幅 ≤ 右の余白 → ① 右に出す
else 推定幅 ≤ 左の余白 → ② 左に出す（現行の flip）
else → ③ 右に出し、max-width で「…」に切る
```
- 行の幅は、**全行を追加した後の1回の読み取り**（既存 `_applyContinuousChordLabelProjection` と同じ段階・同じ方法）で取得する。名前の置き場所を決める用途だけに使い、線の位置には使わない。
- 近似の係数・余白は定数1か所にまとめる。誤差の方向は「やや大きめに見積もる」（右に入らないと判断して左へ回す方向＝切り詰めに頼る頻度を減らす）。
- ③の切り詰め: ラベルに `max-width`（行内の残り幅）と `overflow:hidden; text-overflow:ellipsis` を付ける。

### 構造
- `_buildSectionLayer()` は従来どおり DOM を作る。名前の向きの判定（`--flip` 付与）は、後段（行追加後）の小さな関数 `_placeSectionLabels()` に移す。
- `chartmode.js` は Section の意味を知らないまま。入力は `label` 文字列と位置%だけ。
- 判定結果は `data-label-placement="right|left|clip"` として DOM に残す（検証しやすくする）。

## 5. E — 終了線の上端の四角

- 終了線（`.chart-section-marker--end`）の上端に、**6px の四角**（`::before` 疑似要素。DOM 追加なし）。
- 色は線と同じ `--section-marker-color`。silver は明るい縁 1px を検討（§2.5）。
- 名前なし。隣接境界では終了線自体が出ないので変化なし。
- 1コード分の隙間: 終了線と次の開始線は近づくが、四角は終了線側のみで、開始線は Header 段まで伸びる別の形のため区別できる（モックで確認済み）。実機で再確認。
