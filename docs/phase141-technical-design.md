## 0. 目的（Product Intent）

歌詞のない Chart Mode で、曲のどこからどこまでが何の Section かを直感的に確認できること。
Section は「地図」であり、Chord の意味づけや排他的な区分ではない。
色は目立たせるためではなく、境界と名前を見失わないための識別情報。

---

## 1. 全体の流れ

```
Authority              Projection                    Rendering
analysis.raw.sections → buildSectionMarkerProjection() → Chart Section Marker → Chart Section Layer
 (保存済み Section)     (何を・どこに描くかのデータ化)    (chartmode.js: 汎用アンカー)   (行ごとの描画層)
```

| 層 | 役割 | 知ってよいこと |
|---|---|---|
| Authority | Section の正本（array順もそのまま保持） | Section Model |
| `buildSectionMarkerProjection()`（Section→描画指示への変換） | 「何を・どこに描くか」を作る | Section / 色割当 / 隣接判定 |
| chartmode.js | 受け取ったアンカーを描くだけ | Section Model・Type の意味は **知らない** |

### Projection の出力（汎用アンカー）
```
{ sectionId, chordId, edge: 'start'|'end', label?: string, colorToken: 'sec-0'..'sec-3' }
```
- `label` は start のみ（end には名前を出さない）。

## 2. データの取得元

- 閲覧時は **保存済み `analysis.raw.sections`** を読む。
- `getSections(session)`（編集セッション用・reconcile を呼ぶ）は閲覧では使わない。
- 編集中は従来どおり Section Preview（金色）。Section Marker は **閲覧（Continuous）専用**。

## 3. 表示ルール（合意10項目）

| # | ルール |
|---|---|
| 1 | Section 開始 → 線 ＋ Section 名（開始位置） |
| 2 | 隣接する Section → 境界は **1本** |
| 3 | Section 間に隙間 → 終了線 ＋ 開始線（2本） |
| 4 | Chord を共有 → 実際の終了位置・開始位置にそれぞれ線 |
| 5 | 終了線には名前を付けない |
| 6 | Chord 側に縞模様などの特別表現はしない |
| 7 | Section は排他的として扱わない（重なり OK） |
| 8 | 開始 Chord が見つからない → **何も出さない**（補完・推測しない） |
| 9 | 表示の初期値は ON |
| 10 | 色は「識別」だけの意味。低彩度・少数パレット |

### 隣接判定（ピクセルでなく Chord 配列の index）
```
どれかの Section の startIdx == この Section の endIdx + 1  → 隣接 → 終了線を出さない（開始線の1本のみ）
それ以外                                                    → 終了線 ＋ 開始線
```
- 開始線: 開始 Chord の **最初のセグメント**の左端
- 終了線: 終了 Chord の **最後のセグメント**の右端（隣接でない場合のみ）
- Chord が小節をまたぐ場合、同じ chordId のセグメントが複数小節にできるため、上記のとおり最初／最後を使う。
- 各曲の最後の Section には次がないため、終了線が出る。
- 終了 Chord が見つからない／開始より前の Section は、開始線のみ（終了線は補完しない）。

## 4. 色

- Section の Type では決めない。
- 低彩度 **4色**（`sec-0`〜`sec-3`）を、**Chart上の Section 開始位置順**に循環割当。
```
開始位置が早い順:  1→sec-0  2→sec-1  3→sec-2  4→sec-3  5→sec-0 ...
```
- 色の意味は「同じ Section の開始線・終了線・名前は同じ色」だけ。
- 4色循環のため、開始位置が連続する Section は必ず別色。

### 色割当用の一時順序（重要）
- Projection 内で **表示用の一時配列** を作り、開始 Chord の Chord配列 index で昇順に並べる。
- 開始位置が同じ（同一 index）場合のみ、`analysis.raw.sections` の array 順で決める。
- 開始 Chord が見つからない Section は一時配列に入れない（何も出さず、色番号も消費しない）。
- この順序は **色割当のためだけの Projection 上の順序** であり、Section の「表示順」「管理順」を決めるものではない。
- `analysis.raw.sections` の array 順は変更しない（Authority のまま）。
- 効果: #95（Section 並べ替え）で保存順が変わっても Chart 上の色は変わらない。

### テーマ別の色（確定: 2026-10-05、実機の画面で目視確認済み）

方針: 色の強さを揃えるのではなく、**各テーマで Section 名・境界線が読める**ように調整する。
アプリのテーマは dark（標準・default と同じ配色）/ silver / blue の3つ。実装は `theme.css` の `--section-color-0..3`。

| テーマ | 強さ | sec-0 | sec-1 | sec-2 | sec-3 |
|---|---|---|---|---|---|
| dark | 標準 | `#5FB3AB` | `#7C9BD6` | `#B592C4` | `#C9A15C` |
| silver | 強め | `#00746B` | `#2F55A8` | `#8A3FA0` | `#9A5B00` |
| blue | 標準 | `#1F6F69` | `#3F5A9A` | `#7A5287` | `#86602A` |

**実際の背景色とコントラスト比（実機の画面から測定。モック時の想定を訂正）**

| テーマ | 段の背景（名前が載る） | 小節の背景（線が通る） | 名前の比 | 小節内の線の比 |
|---|---|---|---|---|
| dark | `#0f1117` | `#0f1117` | 6.8〜7.9 | 6.8〜7.9 |
| silver | `#a8acb4` | 約 `#6c6f77`（暗いグレーの半透明） | 2.4〜3.1 | 1.1〜1.4 |
| blue | `#c8dff0` | `#c8dff0` | 4.1〜4.9 | 4.1〜4.9 |

- モック時は silver の背景を `#e8eaee`、blue を `#d5ecf9` と想定していたが、実際のアプリではどちらも暗め（silver は暗いグレーの小節を中間のグレーの上に置く配色）。
- 数値上は silver が低いが、実機の画面で「モック通りで見やすい」とたかっちが判断したため、**色は現状のまま確定**。読みにくいという声が出たら見直す（候補: silver の線に細い明るい縁取り）。
- 「強め」は最大値にしない（必要十分で止める）。
- 色はテーマトークンのみで持ち、JS側は `colorToken`（`sec-0`..）しか知らない。

## 5. 描画構造（Continuous 経路）

```
#chart-grid
 └ .chart-row  (Layer がある行だけ position:relative / 開始を含む行だけ上に Header 段の余白)
     ├ .chart-measure ×N(1〜4)  … 既存（overflow:hidden のため線は入れられない）
     └ .chart-section-layer     … 新規, absolute, pointer-events:none
         └ 小節と同数の空セル（flex:1, 同じ gap）に % で線を配置
```
- Header 用の段（名前を載せる帯、高さ `--chart-section-lane-height` = 24px）は **開始を含む行だけ**に確保。
- 開始線は Header 段まで伸ばして名前を載せる。終了線は小節の中だけで名前なし。
- 行の右寄り（約6割より右）の開始線では、名前を線の左側に出す。
- 線は丸め（小節頭へのスナップ）をせず、実際の位置に置く。
- チャートは 1〜4 列の切り替えがある（`measuresPerRow`）。Layer は列数に依らない。
- 再描画時の `scrollTop` 保存・復元は既存の `renderChartMode()` に従う。
- 再生追従（`_updateContinuousPlayback()`）は Section と無関係。

### 二重管理の防止（Risk Check の結論）
Layer は小節の幅・間隔を「写す」ため、次の3点で二重管理を防ぐ。
1. **共通の定義**: 行の gap（4px）・右余白（16px）・小節の枠の太さ（1px）を CSS 変数（`--chart-row-gap` / `--chart-row-pad-right` / `--chart-measure-border-width`）にまとめ、`.chart-row`・`.chart-measure`・Layer が同じ変数を参照する。
2. **同じループで生成**: Layer の空セルは、行を作る既存ループ内で「その行の小節リスト」から作る（最後の行が短くても、小節と同数になる＝`flex:1` で同じ幅に広がる）。
3. **px計測をしない**: 位置は小節内の % のみ。ウィンドウ幅変更に追従する処理が不要（現状 `chartmode.js` には ResizeObserver がない）。

不採用案: Chord Label Projection と同じ「描画後に DOM の実寸を測る」方式 → 幅変更時の再計測が必要になるため。

### fallback 表示では Section Marker を出さない（確定: 2026-10-05）
- 対象: タイミング情報がなく、小節の位置が決まらない表示（`_renderFallbackGrid`）。
- 理由: Section 表示の目的は名前ではなく「Chart 上の位置関係を含めた曲の地図」。開始位置を正しく決められない表示で名前だけを置くのは、「補完・推測しない」方針に反する。
- 動作: 何も表示しない（エラー表示も出さない）。
