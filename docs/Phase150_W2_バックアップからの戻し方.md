# バックアップからの戻し方（Phase150 W2 縮小版）

保存に失敗したときや、保存後に内容がおかしいときに、**手で元に戻す**ための1ページです。
`section_txn.py` は失敗しても、一時ファイルとバックアップを**自動では消しません**。

## 1. 先に確認すること

```
保存失敗 → エラーの reason を見る
   ├─ 正本（解析ファイル）が無事 → 戻す必要なし。残骸を確認して手で整理
   └─ 正本がおかしい／reason が indeterminate・post-verify-failed → 3 で確認してから 4 で戻す
```

| reason | 意味 | まずやること |
|---|---|---|
| `indeterminate` / `post-verify-failed` | 置換後の確認で決着がつかなかった | **何も動かさず**、3 の「戻す前の確認」で正本・Journal・バックアップを見比べる |
| `tmp-exists` / `journal-corrupt` / `backup-failed`(`bak-part-present`) | 前回の残骸があるため保存を止めた | 残骸は消さずに確認。内容を確認してから手で移動・削除 |
| `write-failed` / `replace-failed` など | 保存前の失敗 | 正本は通常そのまま。確認だけ |

## 2. 置き場所

```
<analysisフォルダ>/
  <projectId>.json                         ← 正本
  _txn/backup/<projectId>/<UTC>_<sha32>.bak ← 保存前バックアップ（新しい順に2世代）
  _txn/tmp/<txnId>.tmp                     ← 書きかけの新内容（未保存の編集が入っている可能性）
  _txn/journal/<txnId>.json                ← 保存の記録（prepared/committed/aborted/indeterminate）
```

## 3. 戻す前の確認（先に必ず）

最新の `.bak` が「正しい戻し先」とは限りません。保存自体は成功していて、正本がすでに新しい内容になっていることもあります（その場合に戻すと、保存済みの編集を失います）。

```
正本・Journal(h0/h1)・最新の .bak を見比べる
 ├─ 正本の内容 ＝ 新内容(h1)  → 戻さない（保存済み）
 ├─ 正本の内容 ＝ 元の内容(h0) → 戻さない（変わっていない）
 ├─ どちらでもない（壊れている等）→ 戻し元の .bak を検証（下記）→ 一致すれば 4 の手順で戻す
 └─ Journal が読めない／判断できない → 何も上書きしない。ファイルを全部残して確認する
```

**戻し元の検証（必須）**：最新の `.bak` の**ファイル全体**の SHA-256 を計算し、Journal の h0（全桁）と比べます。
- 一致 → 戻し元として使えます。
- 不一致・計算できない・Journal の h0 が取れない → **上書きしない**。その `.bak` は使わず、別の（古い）`.bak` を同じ方法で検証するか、ファイルを全部残して確認します。
- ファイル名の32桁は先頭だけなので、名前の一致だけでは検証になりません。

- h0 は元の内容、h1 は新しい内容のSHA-256（Journal に記録）です。`.bak` のファイル名の末尾32桁は h0 の先頭です。
- 迷ったら**上書きしない**。残しておけば後からいつでも戻せます。

## 4. 戻し方（正本をバックアップから戻す）

1. **今の正本をコピーして退避**する（例 `<projectId>.json.broken`）。
2. `_txn/backup/<projectId>/` の中で、**一番新しい `.bak`** を選ぶ（ファイル名の先頭が日時）。
3. その `.bak` を**コピー**して正本に置き換える（バックアップ自体は残す）。
4. アプリを開き、Section とコード譜が表示されることを確認する。
5. 問題なければ、退避したファイルと `_txn/tmp` の残骸を、中身を確認してから整理する。

注意
- `.bak.part` と `.journal.part` は**書込み途中の残骸**です。戻し元には使わず、そのまま残します。
- `_txn/tmp/*.tmp` には保存しきれなかった編集が入っている場合があります。消す前に必ず開いて確認してください。
- この手順は試験（`RestoreDrillTests`）で、試験用フォルダ上で実際に確かめています。Windows 実機での確認は W9（未実施）です。

## 5. 起動時の `recover()`（コードの動き）

- Journal が `prepared`（保存の途中）で止まっているものだけを、**実際の正本と照合**して決着させます。
  - 正本が元のまま → `aborted`
  - 正本が新内容に一致 → `committed`
  - どちらでもない → `indeterminate`（**自動では動かしません**）
- `indeterminate` は人が確認するまで残ります。tmp・バックアップは削除しません。
