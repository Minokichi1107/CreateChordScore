## 1. 経緯の要点

- 小節頭補正は2種類を両方使えるようにする：①指定位置以降だけ組み直す（#101）／②曲全体を指定位置基準に組み直す（#129）。作る順序は②が先
- 操作は右クリックメニューから選ぶ。②は「曲全体をここ基準に組み直す」。「小節補正を解除」で元に戻せる
- ②初回の範囲：4/4拍子・既存の拍だけを指定できる。4/4以外と `beat-only` は設定不可で、理由を短く通知する
- 曲の最初に余った拍（最大3拍）は、短い小節として先頭に出す（弱起と同じ見せ方）
- 将来はセクションごとに小節を表示する仕組みを目指す（今回の仕様ではない）

## 2. 補正ルールと計算式

```
rule = { version: 1, type: 'wholeSongDownbeat', beatTime }
```
- **現在の保存値は `wholeSongDownbeat`（実装・マージ済み）。** 設計時は「type は仮名」としていたが、その意味は「将来、名称を見直す余地がある」ということ。名称を変える場合は、保存済みデータと旧バージョンとの互換性を含む**別の設計判断**になる
- `idx` = `raw.beats` 配列の**0始まりの番号**（先頭の拍が `idx=0`、2番目の拍が `idx=1`）。`beatTime` と一致する拍を探す
- `n` = 1小節の拍数（4）、`r = idx % n`
- 補正後の下拍 = 「`r > 0` なら `beats[0]`」＋「`beats[r], beats[r+n], beats[r+2n], …`」
- 結果：`r = 0` なら先頭から4拍ずつ。 `r = 1,2,3` なら、先頭に**1・2・3拍の短い小節**ができ、指定した拍が次の小節頭になる
- `raw.beats` / `raw.downbeats` は変更しない。補正後の下拍は実行時に作るだけで、保存しない
- 既存の `applyAnchorRepair()`（①の補正）は変更しない。`type` で振り分ける
- `beatTime` は旧アプリの上書き確認（`beatTime.toFixed()`）のために必須（コード読み取りに基づく想定。旧アプリでの実機確認は未実施）

先頭の短い小節に、既存の弱起判定（閾値そのまま）が当たる割合：1拍 94/101、2拍 90/102、3拍 50/100。→ 拍数にかかわらず「印」で確実に弱起扱いにする。

## 4. 短い先頭小節の「印」の設計

- **管理する場所：** `timing.js`。`createTimingModel()` が、`wholeSongDownbeat` で `r > 0` のときだけ、先頭の小節に `isLeading: true` を付ける（実行時に作るだけで保存しない）
- **参照する場所：**
  1. `chartmode.js` の小節のコピー2か所（`buildGridViewModel()` 138〜143行付近、連続表示側 350行付近）で `isLeading` も引き継ぐ
  2. `detectPickupMeasure()` の先頭で、`measures[0]?.isLeading === true` なら `true` を返す。**閾値（0.75倍、±30%）は変更しない**
- 印が無い曲（①の補正、補正なし、旧形式）は、従来どおりの判定になる
- 弱起になったあとの表示（先頭の空きスロット、小節番号「0」）は、既存の処理をそのまま使う

## 5. 置き換えと解除の経路

- 設定：`onSetRepairRule` → 確認ダイアログ → `saveAnalysisFile(raw, 新しいルール)` → `repairRule` を新しいルールに上書き
- 解除：`onClearRepairRule` → `saveAnalysisFile(raw, null)` → `repairRule = null`
- 描画：2つの描画経路が、毎回 `createTimingModel({beats, downbeats, repairRule})` で小節を作り直す。`raw` も小節も保存・書き換えされない
- 「ルールが消える」はコードの経路で確認済み。「元の構造が復元される」は設計上そうなる（小節が `raw` と現在のルールだけから作られる）。画面を通した確認は、実装後に実機で行い問題なし（第8章参照）

## 7. 注意点（製品として）

- ②は元の下拍を使わず拍を並べ直すため、曲の途中で拍子が変わる曲では、正しかった区間もずれることがある。そのときは①や解除を使う
- 検証は24曲・4/4のみ
