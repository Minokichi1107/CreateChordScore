v2 の続き。F5 の原因候補（`quantizeTime()` が小節開始時刻に一致する拍を見つけられず `beatInMeasure = 0` に落ちる）を、実コードの通過回数で直接確認した記録。設計は確定しない。GitHub Issue・commit・push・作者情報・元リポジトリは変更していない。

## 実行条件
- 対象コード：CreateChordScore `aa470f9`。`.git` を除いた作業用コピー（scratchpad `verify/repo`）。
- 環境：Node v22.22.0。データ：231曲（`data.json`、sha256 先頭 54ff0fcd208c09d8）、解析済みの実拍・実小節・実コード開始時刻。
- 3つの `timing.js`（いずれも作業用コピー）：
  - **orig**：実コードそのまま（sha256 9ade79ba…、v2 と同一）。
  - **instr**：`beats.findIndex` の直後に「フォールバックしたか」を記録する1行だけ追加（挙動は変えない）。
  - **patched（反事実）**：フォールバック分岐でだけ、`beatInMeasure` の代わりに「小節開始スロットからの距離」で `slot` を数える。他は orig と同一。**製品の修正案ではなく、原因確認のための実験**。
- スクリプト：scratchpad `verify/c1.mjs`、結果 `verify/c1_result.json`。

## 読み取り（実測と推論を分ける）
- 【実測】＆頭の小節では、**全スロットで** フォールバックが通る。拍頭の小節・実曲では通らない（実曲は開始時刻がすべて拍上のため）。
- 【実測】＆頭の不一致 260,546 件は**すべてフォールバックを通っており**、フォールバックを通らない不一致は 0 件。
- 【実測】フォールバック分岐だけを「小節開始スロットからの距離」に変えると、＆頭の不一致は 260,546 → 3,658 に減る。残りの水準（約1.4%・20曲）は、拍頭の現行値（3,670・20曲）とほぼ同じ。
- 【実測】拍頭の不一致 3,670 件はフォールバックと無関係（0 回）。patched でも変わらない。v2 のとおり局所幅（H2）でのみ解消する。
- 【推論の更新】F5 の＆頭不一致の主因は「フォールバック」であると、実コードの通過回数と分岐だけの変更で裏付けられた（変種の再実装による推論から、実コードでの確認へ上がった）。偶奇判定は原因ではない（v2）。
- 【推論】V3 の差 0（偶奇のみ／小節開始スロット基準の変種）は、実曲に拍上でない小節がなく、フォールバックが一度も通らないことから、構造的に差が出ない条件だったと説明できる。非退行の判別力は限定的（旧 C2）。

## 限界・未確認
- ＆頭の小節区切りは合成（現行コードの修復経路では生成できない）。実アプリの小節頭補正の経路で作った小節ではない。
- patched は原因確認用の実験で、実装案の承認・採用を意味しない。patched と orig の不一致 3,658／3,670 は件数の比較で、同一スロット集合かどうかは照合していない。
- 残りの約1.4%（フォールバック無し）の原因は本検証の対象外（v2：局所幅で解消）。H2 の範囲判断は別。
- 往復はスロット時刻をちょうど置いた場合のみ。実際のコード開始時刻のばらつきは含まない。231曲・解析データの範囲。
- V7、右クリック（編集・通常）、実アプリの目視、`overflow` 変更の副作用は未実施（v2 と同じ）。
