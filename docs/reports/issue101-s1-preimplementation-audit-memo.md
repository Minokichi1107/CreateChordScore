本メモは、S1（slot boundary validation / スロット境界の検証）の既存設計資料について、方式の前提を整合させ、未決事項と実装前の確認順序を明確にするもの。コード変更、テスト実装・実行、コミット、GitHub Issue投稿は行っていない。

## 2. 既存資料の状態

### 2.1 既に選択済みと記載されている方針
- 通常slotは共通幅とし、最後のslotだけを部分幅にしない。
- 不規則小節が1つでもあれば、新方式を部分適用せずチャート全体を既存方式へfallbackする。
- `raw.beats` と `raw.downbeats` を変更しない。
- 末尾領域内にchord onset（コード開始時刻）があれば `TAIL_REGION_CONTAINS_ONSET` を記録し、チャート全体を既存方式へfallbackする（§35のC1）。
- fallback後も診断を保持し、通常表示・編集表示・Section Layerで方式選択を一致させる。

### 2.2 整合性を取るべき箇所
§34は「方式Fか方式Cか」「C1かC2か」をユーザー判断待ちと記載している一方、§35以降は方式C＋C1を選択済みとして記述している。資料全体を読むと、§34の未決表記が古い状態のまま残っている。

**修正案:** §34の状態を「当時の方式比較。後続§35でC＋C1を選択済み。履歴として残す」と明記する。方式FとC2は代替案・不採用案として残し、現在の有効な設計前提と誤読されないようにする。これは資料整合性の修正案であり、ここで新しい製品判断を追加するものではない。

### 2.3 テストIDの重複
§33〜§37で AT-S1-23 以降のIDが再利用されている。例として、§33のAT-S1-23〜28と§37のAT-S1-23以降が異なる条件を指している。§35の追加テストにも独自の連番がある。

**修正案:** テストIDを資料全体で一意に採番し直す。ID変更は参照関係を壊す可能性があるため、テスト内容を確定してから一括で行う。現段階ではIDを独断で振り直さない。

## 3. 末尾slotの基準案
方式Cを基準とする場合、slot領域に含めるのは、開始・終了境界が確定し、終了境界が `audioDuration` 以下である完全slotに限る。終端をまたぐ候補slotは通常slotとして数えず、部分幅slotを生成しない。最後の完全slot終端から音声終端までは独立したtail region（末尾領域）とする。

- 末尾領域の幅が0なら、空の末尾領域は作らない。
- 末尾領域にonsetがある場合はC1に従い、診断を保持してチャート全体を既存方式へfallbackする。
- `audioDuration`と一致するonsetは半開区間 `[lastCompleteSlotEnd, audioDuration)` の末尾領域には含めない。範囲外診断と既存方式側の扱いは別途明記する。
- 方式Cを前提にしても、最終slotの終了境界が外挿由来の場合に完全slotと認める条件は未決である。

## 4. 境界生成契約：確定事項と未決事項

### 境界の出所ラベル案
- `beat`: 入力beatsに実在する拍時刻。
- `interpolated`: 隣接する実在beatの間を分割して生成した境界。
- `extrapolated`: 最終実在beatより後ろに、明示した規則で推定した境界。

ラベルは境界の出所を示す。`extrapolated`を実測beatと同等に扱わない。

### 未決事項
1. 最終beat後の外挿を許可する条件。
2. 外挿間隔を直前1区間・複数区間の代表値等のどれで推定するか。
3. 外挿境界を完全slotの終了境界として認める条件。
4. 有効な正の有限間隔が得られない場合の診断名・fallback契約。
5. 最終小節に完全slotが0個の場合のデータ表現。

**暫定的な安全策:** 正の有限な根拠が説明できない外挿は採用しない。固定0.5秒などの既定値を、新方式の実測境界として扱わない。ただしこれは最終仕様ではない。

## 5. 許容誤差契約
許容誤差は目的ごとに分けて定義する。既存の `BEAT_EPS` を全用途に流用することは、根拠の確認なしには決めない。

| 用途 | 対象 | 実装前に決めること |
|---|---|---|
| downbeat–beat照合 | 小節頭と実在拍 | 許容誤差、候補が複数ある場合の扱い |
| onset分類 | コード開始時刻とslot境界 | 境界一致・近接時の優先規則 |
| 音声終端判定 | slot終端と`audioDuration` | 完全slot判定の比較規則 |
| 重複判定 | 生成された境界同士 | 浮動小数点誤差と実際の重複の区別 |

各許容誤差について、定数名・単位（秒等）・比較演算・境界一致時の優先規則を一組として定義する。特に `lastCompleteSlotEnd` に一致するonsetを末尾領域側とするC1の半開区間規則を、誤差処理が無言で逆転させてはならない。

## 6. 不規則小節契約
チャート全体fallbackという適用範囲は選択済みだが、不規則小節の判定基準は完全には確定していない。

- slotCountが0以下、または境界対応が一意でない場合は、構造異常候補として診断する。
- 標準slotCount超過を不規則小節とする方針候補はあるが、標準値の算出規則を明確にする。
- 標準slotCount未満を自動的に異常としない。短小節、pickup、downbeat欠落を区別する基準は未決。
- #129のpickup／全曲補正を#101に持ち込まない。
- 不規則小節でonsetを黙って捨てたり、slotCountを名目値に切り詰めたりしない。

## 8. テスト整理方針
テスト候補は少なくとも以下の群に分ける。
- 入力の妥当性（beats、downbeats、audioDuration、resolutionPerBeat）。
- 境界の出所（beat / interpolated / extrapolated）。
- downbeatの一意照合と不一致・曖昧さ。
- 小節slotCountと短小節・長小節。
- 最終完全slot、末尾領域、完全slotが0個のケース。
- onsetの通常slot／末尾領域／音声範囲外への分類。
- 複数診断の保持、チャート全体fallback、ビュー間の判定共有。
- `raw.beats`／`raw.downbeats`が変更されないこと。

テストIDは全資料で一意にしたうえで採番する。許容誤差や外挿条件が未決のテストは、数値を仮置きせず条件式で記述する。テスト案は実装・実行結果ではないことを明示する。
