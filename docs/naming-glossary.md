# 命名・用語 対訳表

> 目的: レビュー時に出てくる関数名・変数名・設計用語の「パターン」を理解し、
> コード全体の文脈をすばやく読めるようにするための個人用辞書。
> 分からない単語・パターンに出会ったら随時追記していく。

---

## 1. 関数名のプレフィックス（接頭辞）

| パターン | 意味 | 実例 |
|---|---|---|
| `get○○()` | ○○を取得する。呼んでも状態は変わらない（読み取り専用） | `getCapo()`, `getNormalized()`, `getAudioEl()` |
| `set○○()` | ○○を設定・変更する | `setAudioLoaded()`, `setChordLoaded()`, `setSpeed()` |
| `is○○()` / `is○○` | ○○かどうかを判定する。true/falseを返す | `isSepToken()`, `isChordToken()`, `isRestore` |
| `has○○` | ○○を持っているかどうか | `hasAnalysis`, `hasExisting` |
| `on○○` | ○○というイベント（操作）が起きた時に呼ばれる処理 | `onChordEdit`, `onLineClick`, `onTimeClick` |
| `update○○()` | 既存の○○を最新状態に更新する | `updateChartPlayback()`, `updateStatus()` |
| `render○○()` | ○○を画面に描画する | `renderLines()`, `renderChartMode()`, `renderPalette()` |
| `build○○()` | ○○を新しく組み立てて作る（生成） | `buildGridViewModel()`, `buildNormalizedTimingAnalysis()` |
| `normalize○○()` | 表記がバラバラな○○を統一形式に整える | `normalizeChordName()`, `normalizeProject()` |
| `load○○()` | データを読み込む（ファイル・DB等から） | `loadProj()`, `loadAnalysis()`, `loadAsset()` |
| `save○○()` | データを保存する | `saveProject()`, `saveAsset()`, `saveCustomDiagrams()` |
| `init○○()` | ○○を初期化する（起動時に1回呼ぶ想定） | `initChartMode()`, `initModals()`, `initAudioEngine()` |
| `open○○()` / `close○○()` | モーダルやモードを開く/閉じる | `openChordEdit()`, `closeChartMode()` |
| `refresh○○()` | ○○を再描画・再評価する（軽い再構築） | `refreshEditor()`, `refreshDiagrams()` |
| `detect○○()` | ○○を検出・判定する（やや複雑な判定ロジック） | `detectPickupMeasure()` |
| `_○○()`（先頭アンダースコア） | モジュール内部だけで使う非公開関数（外から呼ばない） | `_renderChartGrid()`, `_startRafLoop()`, `_evaluateBannerState()` |

## 3. このプロジェクト特有の設計用語

これは英語力の話ではなく、設計上の「概念」を表す言葉。
意味を一度理解すれば、どのファイルでも同じ意味で使われている。

| 用語 | イメージ・意味 | たとえ |
|---|---|---|
| **authority**<br>（権限・正本） | 「最終的に正しい値・状態を持っているのはどこか」という宣言。<br>他の場所にある同じような値は「コピー」であり本物ではない。 | 会社の正式な在庫数は倉庫の台帳（authority）。<br>各部署のExcelコピーは便利だが、食い違ったら台帳が正しい。 |
| **ownership**<br>（所有・責任） | 「このデータ・処理を変更していいのは誰（どのモジュール）か」という決まり。<br>ownerではないモジュールは直接書き換えてはいけない。 | 自分の部署の予算は自分たちで使えるが、<br>他部署の予算には手を出せない（予算のownerはその部署）。 |
| **layer**<br>（層） | データが「生データ → 加工データ → 表示用データ」と<br>変換されていく段階。段階ごとに役割が違う。 | 食材（生）→下ごしらえ済み食材→お皿に盛った完成品。<br>同じ「肉」でも段階によって扱い方が違う。 |
| **canonical**<br>（正式形・基準形） | 「これが統一された、基準となる正しい形」という意味。<br>表記ゆれを統一した後の形を指す。 | `Cmaj7` が canonical で、`CM7` や `C△7` は<br>それの別の書き方（alias）。 |
| **projection**<br>（投影・写像） | 元データを「表示用に変換したもの」。<br>変換は一方向で、元データに書き戻されない。 | 鏡に映った自分の姿（projection）。<br>鏡の中の姿を変えても本人は変わらない。 |
| **restore**<br>（復元） | 保存されていたデータから元の状態を再構築すること。 | バックアップからファイルを復元する。 |
| **invariant**<br>（不変条件・絶対ルール） | 「システムが正しく動くために、常に守られていなければならない条件」。<br>これが崩れるとバグになる。 | 「金庫の鍵は常に1本しか存在しない」というルール。<br>増えても減ってもおかしくなる。 |
| **rebuild**<br>（再構築） | キャッシュ的なデータを、元データから作り直すこと。 | 下書きを元データから作り直す（手書きメモは消えない）。 |
| **derived（data）**<br>（派生データ） | 元データから計算して作られた、二次的なデータ。<br>削除しても元データから再生成できる。 | 売上データから作った「グラフ」。<br>グラフを消しても売上データ自体は残る。 |
| **disposable**<br>（使い捨て可能） | いつでも安全に破棄・再生成できるデータという意味。 | キャッシュファイル。消しても再生成すれば元に戻る。 |
| **idempotent**<br>（冪等） | 同じ処理を何度実行しても、結果が変わらないこと。 | 電気のスイッチを「ON」にする操作を何度繰り返しても<br>結果は「ONのまま」。 |
| **transaction**<br>（一連の処理のまとまり） | 複数の処理を「ひとまとまり」として扱い、<br>途中経過は外から見えないようにすること。 | 銀行の振込処理。「引いて」「足す」が両方完了するまで<br>途中状態は他人に見せない。 |
| **mutation**<br>（変更・書き換え） | データの内容を直接書き換えること。 | ノートに直接書き込む（元の内容が変わる）。 |
| **destructive**<br>（破壊的） | 元のデータを書き換えてしまう方式。元に戻せない場合がある。 | 上書き保存（destructive）vs 別名保存（non-destructive）。 |

## 4. よく出てくる略語・複合語

| 表記 | 読み方・正式名 | 意味 |
|---|---|---|
| `idx` | index（インデックス） | 配列などの「何番目か」を表す番号 |
| `cb` | callback（コールバック） | 「後で呼んでもらう関数」 |
| `el` | element（エレメント） | DOM要素（HTML上の部品） |
| `cfg` | configuration（コンフィグ） | 設定 |
| `ui` | user interface | 画面・操作部分 |
| `db` | database | データベース |
| `fmt` | format（フォーマット） | 表示形式に整える |
| `temp` / `tmp` | temporary（テンポラリ） | 一時的な・後で消す予定の |

## 使い方メモ

- レビュー中に分からない単語・パターンに出会ったら、この表に追記する

- 月1回くらい見直して、もう不要になった項目（完全に覚えたもの）はそのまま残してOK（辞書として育てる）
