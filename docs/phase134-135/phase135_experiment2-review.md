```
  「曲中の約2倍のBeat密度変化」を説明できない可能性が高まった

```

### まだ言えないこと（結論にしないこと）

```
・ChordMiniが93baeafd前半で1拍おきにBeatを検出している、という
  断定にはまだ至らない
・93baeafdがHalf-time / Double-time的な音楽構造を持つ、という
  断定にもまだ至らない
・Beat Cursorの違和感の原因がBeatデータ側（Layer A/B）にある、
  という断定はできない
・Beat Cursorの違和感の原因がChart Modeの表示処理側（Layer C）に
  ある、という断定もできない
```

**特に明記すべき点**: 今回のExperiment 2は「93baeafdの密度変化が
比較曲には無い固有の現象である」ことを示しただけであり、
その固有の現象が**ChordMiniの検出上の問題なのか、実際の音楽的な
構造なのか**を区別する材料には、まだなっていない。
この区別（A/B）は、Experiment 2の範囲外のまま残っている。

## 最後のご依頼: Candidate AとBの優先順位

**以下は提案であり、確定事項ではない。**

### 提案: Candidate A（比較3曲のCursor観察）を先に行う

理由を3点に分けて整理する。

```
1. 追加コストがほぼ無い
   比較3曲は既にExperiment 2で選定・再生済みであり、新たな選曲・
   音源準備が不要。「同じ3曲を、今度はCursorに注目して見直す」
   だけで済む。Candidate B（音源の中間点を音楽的に慎重に聴き
   分ける作業）より着手コストが明確に低い。

2. Candidate Bの結果を解釈する土台になる
   仮にCandidate Bを先に行い「前半の中間点に確かにパルスがある
   （A寄り）」と分かったとしても、それだけでは「だからCursorの
   違和感が説明される」とは言えない。前回整理した通り、Cursorの
   離散ジャンプという見え方自体は、A・Bどちらの原因であっても
   同じように起こりうる（Layer Cの性質）。したがって、Cursorの
   違和感がそもそも「Layer Cに一般的な性質」なのか「93baeafd
   固有の何か」なのかを先に切り分けておいた方が、Candidate Bの
   結果を後から解釈しやすくなる。

3. 「今回最も気になっている症状」に直結している
   ここまでの一連のやり取りで具体的に問題として報告されたのは
   「Beat Cursorの見え方」であり、Beat Model自体の理論的な定義
   ではない。Candidate Aはこの具体的な症状に最も近い位置にある
   確認作業であり、先に着手する動機が強い。
```

### Candidate Bを軽視しているわけではない点の補足

```
Candidate Aだけでは、93baeafd固有の密度変化がA（検出漏れ）なのか
B（音楽的構造）なのかという、Beat Model議論の本題そのものには
一切近づけない。Candidate Aは「Cursorの違和感の切り分け」に有効な
だけであり、「Beat Modelの解釈確定」にはCandidate Bが依然として
唯一の直接的な手段のまま残る。

したがって「Aを先に」という提案は「Bが不要」という意味ではなく、
「現時点の不確実性を効率よく減らす順序として、コストの低いAを
先に済ませ、その結果を踏まえた上でBに着手する」という順序の
提案に留まる。
```
