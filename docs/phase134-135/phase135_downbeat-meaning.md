# Phase135続き — Downbeatの音楽的な意味（3つの側面の整理）

> **位置づけ**: 「Downbeatとは、音楽的には何を指すのか？」という問いに
> 限定した整理。モデルI/II/III・A/B/Cの組み合わせ比較には進まない。
> **CreateChordScoreの実装を基準に定義しない。** 既存実装（timing.jsの
> ASSUMPTION・detectPickupMeasure()等）は前回同様「現在の実装が
> 置いている前提」として参考にするだけで、定義そのものには使わない。
> 検証方法・補正方法・アルゴリズム・コード変更には進まない。

---

## 0. 3つの側面

ご指定の通り、Downbeatという1つの言葉には、少なくとも次の3つの
異なる側面が混在している。

```
① 構造上の「1拍目・起点」としてのDownbeat
   … 拍子・小節という記譜上の枠組みが定める「位置」

② 演奏上の「強拍・アクセント」としてのDownbeat
   … 実際の演奏で、その瞬間に音がどれだけ強調されているかという
     音響的・物理的な性質

③ 聴感上の「着地・周期の始まり」としてのDownbeat
   … 聴き手が「ここで一周期が仕切り直された」と感じる、
     知覚・認知上の出来事
```

この3つは、①→③の順に「客観的な枠組み」から「主観的な体験」へと
性質が移っていく。以下、それぞれを詳しく見た上で、一致する場合と
しない場合を整理する。

---

## 1. ①構造上の「1拍目・起点」としてのDownbeat

拍子記号・小節線という記譜上の枠組みによって定まる**位置**である。

```
・「この小節の1拍目はここ」という位置づけは、実際にそこで
  何が鳴っているか（音の有無・強弱）とは無関係に定まる
・休符であっても、前の小節からのタイ（つなぎ）で音が持続していても、
  「1拍目という位置」自体は存在する
・これは音響的な出来事ではなく、拍子というルール（数え方の枠組み）
  が定める抽象的な位置である
```

言い換えると、①は「そこに何か強い音があるかどうか」とは独立した、
**数える上での基準点**という性質を持つ。

---

## 2. ②演奏上の「強拍・アクセント」としてのDownbeat

実際の演奏において、その瞬間の音がどれだけ強調されているかという、
**音響的・物理的な性質**である。

```
・音量（ダイナミクス）
・打楽器のアタック強度
・和音の厚み・音数
・持続時間（アゴーギク的な強調）
```

西洋音楽理論には「拍節的アクセント（metrical accent）」という
考え方があり、慣習的には①（構造上の1拍目）が最も強く演奏される
という前提を置くことが多い（例: 4/4拍子では1拍目が最も強く、
3拍目がそれに次ぐ、という階層構造）。しかしこれはあくまで
**理論上のデフォルトの想定**であり、実際の演奏がそうなっている
保証ではない。

---

## 3. ③聴感上の「着地・周期の始まり」としてのDownbeat

聴き手が「ここで一つの周期（小節）が仕切り直された」「ここに
着地した」と感じる、**知覚・認知上の出来事**である。

```
・和声の変化（コードチェンジ）が「ここで一区切り」という
  感覚を強める場合がある
・旋律のフレーズの切れ目が知覚に影響する
・ダンス・身体の動きとの同期（エントレインメント）が影響する
・聴き手自身のジャンルへの慣れ・学習した予測パターンが影響する
```

重要なのは、③は**聴き手ごとに異なりうる主観的な体験**だという点
である。同じ演奏を聴いても、聴き手によって「どこが1拍目に感じられるか」
の答えが割れることがある（後述）。

---

## 4. 3つが一致するケース（典型・デフォルトの想定）

多くのシンプルな音楽（拍の強弱がはっきりした行進曲、素朴な
童謡・民謡など）では、①②③はおおむね一致する。

```
1拍目という位置（①）に
  → 実際に強い音が置かれ（②）
    → 聴き手もそこを周期の始まりと感じる（③）
```

これが「素朴な想定」であり、Beat Modelの議論で確立した
「楽曲本来のリズム変化と解析異常を区別する」という原則における
「基準となる典型例」の1つとして位置づけられる。

---

## 5. 3つが一致しないケース（音楽的な現象の類型）

以下はいずれも**解析の異常ではなく、音楽そのものの正常な現象**として
広く知られているものである。①〜③の一致・不一致を整理する目的で
類型化する。

### 5-1. シンコペーション（Syncopation）

```
構造上の1拍目（①）はそのままだが、実際の演奏上のアクセント（②）は
弱拍・裏拍に意図的に置かれる。

結果:
  ① と ② が一致しない
  ③（聴感）は、慣れた聴き手であれば依然として構造上の①を
    「本来の周期の始まり」として認識できることが多いが、
    シンコペーションが強い・繰り返される場合には③が②側へ
    引っ張られる（＝アクセントのある方を1拍目のように感じてしまう）
    こともありうる
```

### 5-2. バックビート（ポップス・ロック・ファンクの慣習）

```
4/4拍子の楽曲で、スネアドラム等の強いアクセントが2拍目・4拍目
（バックビート）に意図的に置かれるという、ジャンル上の慣習。

結果:
  構造上の1拍目（①）は変わらないが、実際に最も強く聞こえる音
  （②）は2拍目・4拍目にあることが多い。
  それでも多くの聴き手は、ベース音・和声変化等の他の手がかりから
  ①を「周期の始まり」（③）として認識し続けることが一般的とされる。

  つまりこのケースは「②が①からズレていても、③は①と一致し続ける」
  という組み合わせの実例になる。①②③は独立に動きうることを示す。
```

### 5-3. 休符・タイによって、Downbeat位置に音の出来事が存在しない

```
1拍目（①）が休符、または前の小節から音がタイで持続している場合、
その瞬間に「新しく鳴る音」という意味での②（アクセント）は存在しない。

それでも聴き手（③）は、周期性の学習・予測（エントレインメント）に
よって、音が実際に鳴っていない瞬間にも「拍を感じる」ことができる
ことが知られている。

つまりこのケースは「②が事実上ゼロでも、③は成立しうる」という
組み合わせの実例になる。②の有無と③の成立は別問題ということを示す。
```

### 5-4. 先取り（アナクルーシス的な先行音）

```
1拍目の直前に、次の周期を予告するような音が置かれる（弱起・
ピックアップノートに近い発想。ただし今回は小節単位の弱起ではなく、
フレーズ内の細かい先取りを指す）。

この場合、聴き手の意識（③）は先取り音によって「もうすぐ来る」
という予期を形成し、実際の①への到達を「予期されていた着地」
として強く感じることがある。①への到達そのものが③の成立に
むしろ寄与する、という関係になる。
```

### 5-5. 拍節構造そのものの聴取上の曖昧さ・聴き手間のズレ

```
一部の音楽的文脈（強いシンコペーションが連続する場合、
リズムの慣習が聴き手にとって馴染みのないジャンルの場合等）では、
聴き手によって「どこが1拍目に感じられるか」の答えが実際に割れる
ことが、音楽知覚の研究等で報告されている
（例: 手拍子を裏拍で取ってしまう、という現象は広く知られている）。

このケースでは、③（聴感）が①（構造）と体系的にズレたまま
定着してしまうことがあり、しかもそのズレ方が聴き手によって
異なりうる。つまり③は、①のような単一の「正解」を必ずしも
持たない、という性質を示す実例になる。
```

---

## 6. 整理: ①②③の関係のまとめ

```
①（構造上の位置）
  ・客観的。記譜・拍子というルールによって一意に定まる
  ・音の有無や強弱とは独立に存在しうる

②（演奏上のアクセント）
  ・物理的・音響的。演奏（録音）ごとに異なりうる
  ・①と一致することが多いが、ジャンルや表現意図により
    意図的にズレることがある（5-1, 5-2）
  ・①の位置に音そのものが存在しないこともある（5-3）

③（聴感上の着地）
  ・主観的・知覚的。聴き手ごとに異なりうる
  ・②が無くても③は成立しうる（5-3）
  ・②が①からズレていても③は①のまま保たれることがある（5-2）
  ・逆に③が①からズレて定着することもありうる（5-5）
```

3つは独立に動きうる、というのがここまでの整理の結論である。
**ただし、これは「①②③の関係をモデル化する（例えばモデルI/II/III
のような形で）」というところまでは踏み込んでいない。** 今回は
あくまで「音楽的にこの3つの側面が別物であり、一致しないケースが
実際に存在する」という事実の整理に留める。

## 7. 既存の方針との整合（維持事項の再確認）

```
・Beatが数学的な等間隔を要求しないのと同様に、Downbeatについても
  ①②③の不一致（5-1〜5-5）は、それ自体では「異常」ではなく、
  音楽そのものが持ちうる正常な性質として扱う

・したがって、①②③のいずれかがズレて観測された場合も、
  「楽曲本来の音楽的現象なのか」「ChordMiniの解析異常なのか」
  「CreateChordScore側の処理バグなのか」という、Beat Modelで
  確立した3分類の切り分けが、Downbeatについても同様に必要になる
  （今回はこの切り分けの具体的な方法には踏み込まない）
```

## 8. 既存実装の前提との関係（参考情報としてのみ）

```
timing.jsの [ASSUMPTION]（measure.startTimeはraw.beatsのいずれかと
一致する）は、暗黙に「Downbeat＝①（構造上の位置）であり、かつ
それは常に何らかのBeatと時刻が一致する」という前提を置いている
ように読める。ただしこれは実装上の前提であり、①②③の音楽的な
関係を定義するものとしては採用しない。

detectPickupMeasure()は、measuresの長さという統計量のみで
弱起小節を判定しており、②（実際のアクセント）や③（聴感）には
一切触れていない。つまり既存実装は事実上①（構造上の位置。
しかもraw.downbeatsという検出結果に基づく位置）のみを
Downbeatとして扱っている、と読み取れる。この読み取り自体は
参考情報であり、「実装がそうしているから①だけを採用する」
という結論には結び付けない。
```

## 9. 本ファイルで確定したこと・していないこと

**確定したこと**: 「Downbeat」という語が、少なくとも①構造・
②演奏アクセント・③聴感、という3つの異なる側面を持ち、これらは
一致するとは限らない（5-1〜5-5のような音楽的現象が実際に存在する）、
という整理のみ。

**していないこと（ご指定の通りすべて保留）**:
```
・Downbeat = Beatの部分集合
・DownbeatとBeatは独立した軸
・DownbeatからBeatを導出する
・Downbeat = Measureの境界
・timeSignatureとの具体的な整合ルール
・Pickup Measureの具体的な処理
・①②③のうちどれを「CreateChordScoreが扱うべきDownbeat」とするか
・検証方法
・補正方法
・アルゴリズム
・コード変更
```

次にBeatとの関係（モデルI/II/III等）へ戻る際は、今回整理した
①②③のどの側面を念頭に置いた議論なのかを意識する必要がある、
という点だけを申し送り事項として記録しておく。
