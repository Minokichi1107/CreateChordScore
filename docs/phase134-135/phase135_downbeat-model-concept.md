## 1. Downbeatとは何を意味するのか

Downbeatという語は、指揮者が指揮棒を振り下ろす動作（downward beat）に
由来する。ここからいくつかの異なる、しかし関連する意味合いが派生している。

```
(a) 動作としての意味　　　… 小節の最初の拍で指揮棒が下りる、という動作
(b) 位置としての意味　　　… 小節の「1拍目」という構造上のポジション
(c) 機能としての意味　　　… 周期（小節）の「起点」「再出発点」を示す役割
(d) 知覚としての意味　　　… 聞き手が「ここで拍が着地した」と感じる瞬間
```

これらは通常重なり合うが、常に一致するとは限らない、という点が
最初の論点になる。

**論点1-1: Downbeatは「時刻上の点」か「拍節構造上の役割」か**

```
時刻としてのDownbeat: 「この曲のこの瞬間（例: 12.34秒）」という
  1つの具体的な時刻点を指す使い方
役割としてのDownbeat: 「小節の先頭という機能を担う拍」という
  抽象的な位置づけを指す使い方
```

ChordMiniのようなAI解析はDetected Beatと同様に「時刻の配列」として
downbeatsを返す（前回の棚卸しで確認済み・参考情報）。しかし音楽的な
Downbeatの本来の意味は、むしろ「役割」の方に近い可能性がある。
「時刻として記録されたdownbeat」と「役割としてのDownbeat」を同一視
してよいかは、まだ決めていない。

**論点1-2: Downbeatは「構造上の位置」か「実際の強拍（アクセント）」か**

```
構造上の位置としてのDownbeat: 拍子記号・小節線が示す「1拍目」という
  楽譜上の位置。実際に強く演奏されるかどうかとは無関係
実際の強拍としてのDownbeat: 演奏上、実際にアクセントが置かれている拍
```

シンコペーション（Syncopation）のように、楽譜上の1拍目より他の拍の方が
聴感上強く感じられる演奏は一般的にある。この場合でも「1拍目」という
構造上の位置は変わらない、という考え方と、「聴感上の強拍こそが
Downbeatの本質」という考え方の両方がありうる。どちらを採るかで、
後述するBeatとの関係・検出との関係の扱いが変わってくる。

## 2. Beatとの関係は何か

Phase135前半で確立した「Beat＝楽曲のリズムを構成する時間上の基本的な
区切り（等間隔を要求しない）」を踏まえた上で、BeatとDownbeatの関係には
少なくとも3つの異なる捉え方がありうる。

### モデルI: Downbeat ⊂ Beat（Downbeatは特定の性質を持つBeatの一つ）

```
Beatという1つの連続した拍の列があり、そのうちの一部（周期の先頭に
あたるもの）がDownbeatと呼ばれる。

Downbeatは常にBeatの部分集合である、という考え方。
```

これは前回棚卸しで確認した既存コードの暗黙の前提
（`[ASSUMPTION] measure.startTime は必ず raw.beats のいずれかの要素と
一致する`）が採用している考え方に近い。ただしこれはあくまで
**参考情報**であり、この考え方を音楽モデルとして正しいと決めたわけ
ではない。

### モデルII: BeatとDownbeatは別々の軸（独立した2つの層）

```
Beat　　　… 等時的（またはそれに近い）パルスの層。「いつ次の拍が
            来るか」に関わる情報
Downbeat  … 周期的なまとまり（小節）がどこから始まるかを示す層。
            「どの拍が区切りになるか」に関わる情報

この2つは概念的に異なる軸であり、両者が完全に一致する保証は
モデル上は存在しない、という考え方。
```

この見方では、「あるDownbeatが、たまたまBeatの一つと同じ時刻を
指している」ことと、「DownbeatはBeatの部分集合である」ことは、
似ているようで別の主張になる。前者は結果として観測される事実、
後者はモデル上の公理、という違いがある。

### モデルIII: Downbeatが先にあり、Beatはそこから派生する

```
Downbeat（小節の起点）がまず音楽的に存在し、その間隔をtimeSignatureに
従って分割することでBeatが定義される、という考え方。

Beat（等分割）→ Downbeat（その一部）という向き（モデルI）とは、
導出の方向が逆になる。
```

日常的な感覚では「拍を数えて4拍溜まったら小節」という数え方
（モデルIに近い発想）をしがちだが、指揮者が「まず小節の頭をとらえ、
その中を拍で割っていく」という感覚を持つ場合はこちらに近い。
どちらが音楽的により自然かは、演奏・ジャンル・文脈によっても
異なりうる。

**論点2-1**: この3モデルのうち、どれか1つを唯一のモデルとして
採用する必要はないかもしれない。「検出（Detected）の場面ではモデルII
（独立した2つの推定結果として扱う）、音楽的な理解（Musical）の場面
ではモデルI寄りに解釈する」というように、**場面によって異なる
モデルを使い分ける**という可能性も排除しない。

**論点2-2**: Beat側でも「Musical Beat」と「Detected Beat」を区別した
のと同様に、Downbeat側にも「Musical Downbeat」と「Detected Downbeat」
という区別を置くとすれば、以下の4通りの関係を別々に検討する必要が
生まれる。

```
Detected Beat ←→ Detected Downbeat   （検出結果同士の関係）
Musical Beat  ←→ Musical Downbeat    （音楽的概念同士の関係）
Detected Beat ←→ Musical Beat        （Beat側の検証：既存の論点）
Detected Downbeat ←→ Musical Downbeat（Downbeat側の検証：新しい論点）
```

「Detected Beat と Detected Downbeat が一致するとは限らない」ことと
「Musical Beat と Musical Downbeat が一致するとは限らない」ことは、
別の主張である。後者（音楽概念同士の関係）の方がモデルI/II/IIIの
選択に直接関わる。

## 3. 小節（Measure）との関係は何か

### モデルA: Downbeat-primary（Downbeatが先にあり、Measureはその結果）

```
隣接する2つのDownbeatの間の区間として、Measureが事後的に定義される。
```

### モデルB: Measure-primary（Measureが先にあり、Downbeatはその結果）

```
Measure（小節）は、拍子・フレーズ構造・和声進行の周期性など、
Downbeatとは独立した音楽的な単位としてまず存在し、
その先頭にあたる拍が結果的にDownbeatと呼ばれる。
```

### モデルC: 両者は同じものの別名（区別する実益がない）

```
実務上、MeasureとDownbeatを別概念として扱う必要は無く、
「小節の先頭＝Downbeat」という等式がそのまま成り立つ、という考え方。
```

**論点3-1: Pickup Measure（弱起小節）との整合**

このプロジェクトの既存コードには`detectPickupMeasure()`（前回棚卸し
参照）があり、曲頭に不完全な小節（Pickup Measure・弱起）が存在しうる
ことを前提にしている。ここで音楽理論上の緊張関係が生じる。

```
弱起小節の先頭は、伝統的な音楽理論では「Downbeat」ではないとされる
ことが多い（弱起は文字通り「弱い」拍から始まり、その曲の最初の
本当のDownbeat＝1拍目は、弱起部分の後、最初の完全小節の頭に来る、
という考え方）。

一方、実務上（このプロジェクトの既存コードも含め）「小節の境界」
という意味では、弱起小節の先頭も他の小節境界と同列に扱われている
（buildMeasures()はmeasures[0]も他のmeasuresと同じ形状で返す）。

つまり:
  「Measureの境界」という意味でのDownbeat（実務的・位置的な用法）と
  「拍節の強起点」という意味でのDownbeat（伝統的・機能的な用法）は、
  弱起小節の文脈では一致しない可能性がある。
```

この緊張関係をどう扱うか（実務的な「小節境界マーカー」としての
Downbeatと、音楽理論上の「強起点」としてのDownbeatを、そもそも
別の言葉で呼び分けるべきか、あるいは弱起という特殊ケースとして
別途扱うべきか）は、まだ整理していない。

**論点3-2**: モデルAとモデルBのどちらを採るかは、後述する
Slot Model（Phase134で既に論点化されている「1 slotが何を表すか」）
にも影響しうる。Measureが先に決まってからDownbeatを見るのか、
Downbeatの検出結果からMeasureを組み立てるのかで、異常検出の設計
（何を「基準」とみなし、何を「そこからのズレ」とみなすか）の
前提が変わる可能性がある。ただし、これは次フェーズ（Slot Model）
の話であり、ここでは論点の存在だけを記録する。

## 4. timeSignatureとはどのような関係になるのか

### 論点4-1: timeSignatureはDownbeat間隔の「意味」を与えるものか

一般的な理解として、timeSignature（拍子記号）は「1つの小節に何拍
入るか」を示す。この理解に立てば、隣接するDownbeat同士の間隔は
「timeSignatureの分子（numerator）が示す拍数ぶん」ということになる。

ただし、これは「Downbeat間隔からBeat数を数えたらnumeratorに一致する
はず」という**検証すべき仮説**なのか、それとも「timeSignatureが
Downbeat間隔の意味を定義する」という**定義（公理）**なのかで、
扱いが変わる。前者なら「一致しない場合がある」ことを許容し観察する
対象になるし、後者なら一致しないこと自体が定義違反ということになる。

### 論点4-2: 単純拍子と複合拍子での「拍」の数え方の違い

前回棚卸しで確認した既存コード内のコメント`[FIXME-6/8]`
（6/8拍子はnumerator=6としてそのまま扱われているが、音楽的には
2拍系（3+3の複合拍子）であるべき、という既知の未解決事項）は、
まさにこの論点に関わる**参考情報**である。

```
単純拍子（例: 4/4）: 1小節＝4分音符4つ分。「拍」＝4分音符という
  感覚と、記譜上のnumeratorが素直に一致しやすい

複合拍子（例: 6/8）: 記譜上のnumeratorは6だが、音楽的に感じられる
  「拍」は2つ（それぞれが3連符的に3分割される）という感覚の方が
  一般的とされる
```

これは「timeSignature.numerator＝Downbeat間に含まれるBeatの数」
という単純な等式が、拍子の種類によっては成り立たない可能性がある
ことを示す。単純拍子と複合拍子で、そもそも「Beat」という語が
指すもの自体が変わる（複合拍子では「拍」は3分割される単位を
指すのか、その3分割をまとめた単位を指すのか）という、より
根本的な曖昧さが背後にある。

### 論点4-3: timeSignatureは曲全体で1つの固定値か、区間ごとに変わりうるか

現在の解析データ（`raw.timeSignature`）は曲全体に対して1つの
オブジェクトとして与えられている（前回棚卸しで確認・参考情報）。
しかし音楽的には、曲の途中で拍子が変わる（拍子変更・変拍子）ことは
珍しくない。

```
timeSignatureが曲全体で一定である、という前提自体が、
Downbeat-Beat-Measureの関係を考える上での暗黙の単純化になっている
可能性がある。

この単純化を今の段階で受け入れるか、それとも「timeSignatureは
区間ごとに変わりうるもの」として最初からモデルに含めておくかは、
まだ決めていない。
```

### 論点4-4: 何が「原因」で何が「結果」か

```
Downbeat間隔の実測値 → 「この曲はX拍子らしい」と推定する
                        （timeSignatureをDownbeatから導出する向き）

timeSignatureという既知の情報 → Downbeat間隔がその通りになって
                        いるかを確認する
                        （timeSignatureを基準にDownbeatを検証する向き）
```

ChordMini解析では`raw.timeSignature`と`raw.downbeats`は別々に
提供される（前回棚卸しで確認・参考情報）。どちらが「先に与えられる
べき基準」でどちらが「検証される側」かは、データの提供順序とは
別に、音楽モデルとして独立に考える必要がある論点として残る。

## 5. ここまでで浮かび上がった、相互に絡み合う論点の整理

4つの問いは独立ではなく、互いに関係している。

```
§2（Beatとの関係）でモデルI/II/IIIのどれを採るかは、
  §3（Measureとの関係）でモデルA/B/Cのどれを採るかと無関係ではない
  （例: モデルI「Downbeat⊂Beat」を採ると、モデルAの
  「Downbeat-primaryでMeasureを定義する」考え方と相性がよい）

§3の弱起小節（論点3-1）は、§1の「構造上の位置 vs 実際の強拍」
  （論点1-2）とも関係する（弱起小節の先頭を「Downbeatと呼ぶべきか」
  自体が、この2つの立場のどちらを採るかに依存する）

§4の複合拍子問題（論点4-2）は、§2の「Beatとは何を指すか」を
  もう一段複雑にする（複合拍子ではBeat自体の粒度が2重になりうる）
```

このため、4つの問いに個別に1つずつ答えを出すという進め方よりも、
「Beat・Downbeat・Measure・timeSignatureという4つの概念が、
全体としてどういう関係の束（モデル）を成すか」を、いくつかの
候補（例えば モデルI+A、モデルII+B のような組み合わせ）として
比較検討する進め方の方が適しているかもしれない。ただし、これも
次に何をするかの提案であり、本ファイルではここまでに留める。

## 6. 本ファイルで確定したこと・していないこと

**確定したこと**: なし。すべて「検討すべき論点・候補モデルの列挙」
であり、Decisionは1つも含まれていない。

**していないこと**:
```
・Downbeat = Beatの部分集合、という結論
・Downbeat = 小節の最初のBeat、という結論
・Downbeatは必ずbeats上に存在する、という結論
・既存コードの前提（[ASSUMPTION]等）を音楽モデルとして正当化すること
・検証方法・補正方法・アルゴリズムの提案
・コード変更
```

**参考情報として引用したが、モデル決定には使っていないもの**:
```
・timing.jsの[ASSUMPTION]コメント（§2モデルIとの類似を指摘したのみ）
・[FIXME-6/8]コメント（§4論点4-2の実例として引用したのみ）
・detectPickupMeasure()の存在（§3論点3-1の背景として引用したのみ）
・raw.timeSignatureが曲全体で1つのオブジェクトである実装事実
  （§4論点4-3の背景として引用したのみ）
```
