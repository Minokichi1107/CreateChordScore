## 1. Measureとは何か（音楽的概念）

Measure（小節）は、拍（Beat）を一定数まとめた、周期的な単位である。
ただし、この「周期的な単位」という言い方には、少なくとも2つの
異なる捉え方が混在しうる。

```
捉え方I: 拍子（Time Signature）が定める「数える単位」
  … 「4拍でひとまとまり」という、記譜上のグルーピングのルール
  … Measureは「何個のBeatを1つにまとめるか」というルールの適用結果

捉え方II: 音楽的なフレーズ・反復構造の単位
  … 和声の変化・メロディの区切り・反復パターンなど、聴感上
    「ここで一区切り」と感じられる音楽的な単位
  … Measureは必ずしも拍子のルールだけで決まるとは限らない
    （変拍子や自由リズムの楽曲では、拍子記号自体が後付けの
    近似であることもある）
```

これは、前回整理したDownbeatの3側面（①構造・②アクセント・
③聴感）と同じ構造の対立が、Measureという単位にも及ぶことを示す。
捉え方Iは①寄り、捉え方IIは③寄りである。

**論点M-1**: 本プロジェクトが最終的に必要としているのは、
「画面に規則正しく描画するための単位」（捉え方Iに近い、実務的な
グリッド）なのか、「音楽的に意味のある区切り」（捉え方IIに近い）
なのか。両者が一致する曲がほとんどだとしても、一致しない曲
（93baeafdのような）で、どちらを優先するかという判断が必要になる。

---

## 2. Downbeatとの関係（前回整理の要約と接続）

前回、Downbeatには①構造上の位置・②演奏上のアクセント・③聴感上の
着地という3つの側面があり、常に一致するとは限らないことを整理した。

Measureとの関係で言えば、Measure（小節）は「隣接する2つのDownbeat
の間」として素朴には定義できそうに見える。しかし、Downbeat自体が
①②③のどの意味で言われているかによって、Measureの区切り方も
変わりうる。

```
①（構造上のDownbeat）を基準にMeasureを区切る
  → 拍子・記譜上のルールに従った機械的な区切り

③（聴感上のDownbeat）を基準にMeasureを区切る
  → 聴き手が実際に「ここで一区切り」と感じる場所での区切り
  → ①とズレる場合、Measureの境界自体が①③のどちらの基準かで
    変わってしまう
```

**論点M-2**: Measureを「Downbeatの間」として定義する場合、その
Downbeatが①②③のどの意味を指しているかを、Measure Model側でも
明示する必要がある（前回のDownbeat議論を保留のままMeasure Model
へ進むと、この点が曖昧なまま残ってしまう）。

---

## 3. Beatとの関係

§8で確認された作業定義（Beat＝楽曲のリズムを構成する時間上の
基本的な区切り。等間隔を要求しない）を踏まえると、
MeasureとBeatの関係にも複数の捉え方がありうる。

```
捉え方a: Measure = 一定数のBeatの集まり
  … 「4拍集まったら1小節」という、Beatを積み上げてMeasureを
    構成する考え方（Beat-primary）

捉え方b: Measureが先にあり、その中がBeatで分割される
  … 「1小節をN等分すると、それがBeatになる」という、Measureを
    先に定義し、そこからBeatを導出する考え方（Measure-primary）
```

これは前回のBeat-Downbeat関係で整理したモデルI/II/IIIの構図と
類似しており、無関係ではない。ただし今回はDownbeatを介さず、
BeatとMeasureを直接結びつける捉え方として、改めて論点化しておく。

**論点M-3**: 捉え方aと捉え方bのどちらを採るかによって、
「1つのMeasureに含まれるBeatの数」という量が、
「観測された結果（捉え方a）」なのか「あらかじめ決まっている前提
（捉え方b）」なのかが変わる。この違いは、後述する§6（既存実装）
の`beatCount`の扱いと直接関係する論点であり、次のSlot Model検討にも
影響しうる。

## 4. Time Signatureの位置づけ

Time Signature（拍子記号）は、一般には「1小節に何拍入るか」
「1拍が何分音符に相当するか」という2つの情報（分子・分母）を
同時に表す記譜上の約束事である。

```
分子（numerator）… 1小節に含まれる拍の数
分母（denominator）… 1拍として数える音符の長さの単位
```

**論点M-4**: Time Signatureは、Beat/Measureを「定義する」ものか、
それとも実際のBeat/Measureの検出結果を「検証する」ためのものか。

```
定義として使う場合:
  Time Signatureが先にあり、それに従ってMeasure・Beatの数を
  決定する（捉え方bに近い）

検証として使う場合:
  実際に検出されたBeat・Downbeatの並びから、後付けで
  「この曲は4/4らしい」と推定・確認するための情報として使う
  （捉え方aに近い）
```

**論点M-5（複合拍子の扱い）**: 前回も触れた6/8拍子のような複合拍子
では、分子（6）がそのまま「拍の数」を表すのか、それとも「拍を
さらに細分化した単位の数」（音楽的には2拍・各3分割）を表すのかが
曖昧になる。これは分母（denominator）の意味が関わってくる論点だが、
後述の通り、現在のCreateChordScoreの実装は分母を計算に一切使って
いない（§6参照）。これは実装上の事実であり、音楽的にどうあるべきか
という結論には結びつけない。

---

## 5. Pickup Measure（弱起小節）の位置づけ

弱起小節は、曲の冒頭（または楽節の冒頭）が、完全な1小節に満たない
拍数から始まる場合を指す、伝統的な記譜上の概念である。

**論点M-6（前回からの持ち越し）**: 前回のDownbeat議論（論点3-1）
で指摘した通り、弱起小節の先頭は、伝統的な音楽理論では
「Downbeat」とは呼ばれないことが多い（本当の1拍目は弱起の後に来る）。
一方で、実務上「小節の境界」としては、弱起小節の先頭も他の小節と
同列に扱われることが多い。

Measure Modelの文脈でこれを言い換えると：

```
弱起小節は「不完全なMeasure」なのか、それとも「Measureという単位の
外側にある、特別な前置き区間」なのか

前者: 弱起小節も「Measureの1つ」として数える（ただしBeat数が
      他のMeasureより少ない、という例外を許容する）
後者: 弱起小節は「Measure」という単位の定義そのものには含めず、
      別の概念（アウフタクト・pickup区間）として扱う
```

**論点M-7**: 前者を採ると、「Measureは常に一定数のBeatを持つ」
という前提（§3捉え方bの厳格な形）が崩れる。後者を採ると、
「曲の先頭から最初のMeasureが始まるまでの間に、Measureに属さない
区間が存在しうる」という、Measureの通し番号や範囲の定義に
別の考慮が必要になる。

## 6. 既存実装の事実（コード確認・音楽概念とは分離）

ご依頼の通り、リポジトリを実際に確認した。以下はすべて
**「現在のコードがそう書かれている」という事実**であり、
音楽的に正しい・あるべき、という判断は一切含まない。

### 6-1. Measureの構築方法（`buildMeasures()`・timing.js）

```javascript
// fullモード（downbeats使用時）
downbeats.map((startTime, i) => ({
  startTime,
  endTime: downbeats[i+1] ?? (audioDuration ?? startTime + beatsPerMeasure*0.5),
  beatCount: beatsPerMeasure,   // ← timeSignature.numeratorの固定値
  confidence: 'high',
}))

// beat-onlyモード（downbeats不使用時）
// beatsPerMeasure個ずつbeatsをグループ化
```

**事実**: `beatCount`は、その小節に実際に何拍のbeatsが含まれて
いるかを数えた結果ではなく、`timeSignature.numerator`をそのまま
コピーした固定値である（§3の捉え方bに相当する実装になっている）。

### 6-2. Time Signatureの分母は計算に一切使われていない

```
コードベース全体をgrepした結果、denominatorが実際の計算ロジックに
使われている箇所は1つも無かった。唯一の使用箇所は、ヘッダー表示
文字列の組み立て（例: "4/4"という表示テキストの生成）のみ
（chartmode.js）。
```

**事実**: Measure・Beat・Slotのいずれの計算も、分母の値
（4分音符単位か8分音符単位か等）に一切依存していない。
`[FIXME-6/8]`というコメント（既に前回確認済み）は、この実装事実を
裏付けるものだった。

### 6-3. Pickup Measureの扱い

```
detectPickupMeasure(measures) は、既に構築済みのmeasures配列の
「長さの統計」のみで弱起小節を判定する（前回確認済み。再掲）。
判定後、measures[0]は「pickup measure（display上は小節番号0）」
として扱われるが、データ構造上は他のmeasuresと全く同じ形状
（startTime/endTime/beatCount/confidence）を持つ。
```

**事実**: 現在の実装は、§5の論点M-6における「前者」（弱起小節も
Measureの1つとして数える）の立場を、少なくともデータ構造上は
採用している。ただし、これは表示用の番号付け（§9・Phase61の
`getDisplayMeasureNumber()`）を分離することで対応しており、
弱起小節と通常小節を完全に同一視しているわけではない。

### 6-4. Time Signatureは曲全体で単一の固定値

```
normalizeTimeSignature()（analysisLoader.js）は、raw.timeSignature
という1つの文字列を、曲全体に対して1回だけ{numerator, denominator}
へ変換する。区間ごとに異なるtimeSignatureを持たせる仕組みは
存在しない。
```

**事実**: これは前回のDownbeat議論の論点4-3で触れた「timeSignature
は曲全体で一定という前提」が、実装上も文字通りそうなっていることを
裏付ける。

## 7. 音楽概念と実装の一致点・仮定している点

```
一致していると言える点:
  ・「Measure = Downbeatの間」という捉え方（§2）は、
    fullモードのbuildMeasures()の実装（downbeats[i]をそのまま
    小節境界とする）と自然に対応している

実装が「仮定」している点（音楽的に検証されたわけではない）:
  ・beatCountが常にtimeSignature.numeratorと一致する
    （§3捉え方bを暗黙に採用している。実際のbeats数を数えて
    確認していない）
  ・Time Signatureの分母は無視してよい（§4論点M-5・複合拍子の
    音楽的な意味を実装に反映していない）
  ・Time Signatureは曲全体で一定である（§4論点M-4・拍子変更が
    無いことを前提にしている）
  ・弱起小節もMeasureの1つとして扱ってよい（§5論点M-6の「前者」を
    データ構造上は選んでいる。ただし表示番号は分離）
```

## 8. Beat Model側へフィードバックすべき論点

ご依頼に従い、Measure Model検討の中でBeat Model側の見直しが
必要になりそうな点を明示する。**Beat Model自体を今回変更するもの
ではなく、次にBeat Modelへ戻る際に検討すべき論点として記録する
に留める。**

```
論点F-1: 「1つのMeasureに含まれるBeatの数は常に一定か」という問い
  Beat Modelでは「Beat間隔は数学的に一定でなくてよい」という
  緩やかな前提を置いたが、「1つのMeasure内のBeatの"個数"」に
  ついては、Beat Model側では触れていなかった。

  現在の実装（§6-1）は「常にtimeSignature.numeratorと一致する」
  という強い前提を無検証で置いている。93baeafdの実データでは、
  たまたまこの前提が（前半・後半とも常に4拍で）成立していたが
  （前回のFact Check参照）、これは「たまたま」なのか「Beat Modelの
  性質上、必然的にそうなる」のかは、まだBeat Model側で検討されて
  いない。

  次にBeat Modelへ戻る際は、「Beat間隔の揺らぎ」だけでなく
  「Measure内のBeat個数の揺らぎ」も許容範囲に含めるべきかどうかを
  検討する必要がある。
```

```
  どちらを基準とすべきか、あるいは場面によって使い分けるべきか

  （前回から持ち越し・論点M-2）
・BeatとMeasureの関係は捕え方a（Beat-primary）とb（Measure-primary）
  のどちらか、あるいは両立させるか（論点M-3）
・Time Signatureは定義か検証対象か（論点M-4）
・複合拍子（6/8等）における「拍」の粒度をどう扱うか（論点M-5）
・弱起小節をMeasureの一種として扱うか、別概念として扱うか（論点M-6）
・Measure内のBeat個数は常に一定という前提を置いてよいか（論点F-1）
```

## 10. 確定したこと・していないこと

**確定したこと**: §8で共有されたBeat Model Decision 1〜9を
そのまま前提として受け取ったこと、および§6の実装事実の確認。

**していないこと**:
```
・Measureの定義そのもの（捉え方I/IIのどちらか）
・DownbeatとMeasureの関係の確定
・BeatとMeasureの関係の確定（捉え方a/bのどちらか）
・Time Signatureの位置づけの確定（定義か検証対象か）
・弱起小節の扱いの確定
・既存実装（beatCount固定値・分母無視等）が正しいかどうかの評価
・Slot Model・実装変更の提案
```

次に進めるとすれば、§9で列挙した論点のうち、どれから着手するかの
優先順位づけになると考えられるが、これも提案に留め、判断は別途
行っていただく前提とする。
