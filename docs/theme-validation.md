# テーマ検証ガイド

## 目的と適用範囲

実装時のテーマ検証（各テーマで表示・操作を確認する作業）を、毎回同じ判断手順で行うためのガイド。

本ガイドでは、次の2種類を分けて扱う。

- **実データでの実行時検証**：実際のアプリデータを使い、変更した機能がブラウザ上で期待どおりに動くか確認する。
- **合成データでの検証**：特定の表示状態や境界条件を再現するために用意したデータで、表示・状態遷移を確認する。

テーマは dark / silver / blue の3種類。ここで定めるのはテーマ検証の範囲であり、機能の動作確認そのものを省略する規則ではない。

## 判断基準

### 実データでの実行時検証

**dark を基本テーマとする。ただし、差分と関連CSSを調べ、テーマ依存がないと確認できた場合に限る。**

dark のみでよい条件は、次のすべてを満たす場合。

- [ ] 変更差分を確認し、色・背景・枠線・影・透明度など、テーマによって見え方が変わる指定を変更していない。
- [ ] 変更した共通CSSが参照する CSS カスタムプロパティ（CSS変数）について、テーマごとの値・継承・上書きが結果に影響しないことを確認した。
- [ ] 対象要素にテーマ別の上書きルールがなく、またはその上書きが今回の変更と無関係だと確認した。
- [ ] 表示状態・コントラスト・視認性について、特定テーマだけで問題が起きる根拠が見つかっていない。

**追加テーマでの検証が必要な条件**

以下のいずれかに該当する場合、影響を受けるテーマを追加する。

- `css/theme.css` などのテーマ別ルール、テーマ別トークン、色・背景・枠線・影・透明度を変更した。
- 共通CSSの変更が、テーマごとに異なる変数値・継承・テーマ別上書きに依存している。
- 対象クラスにテーマ固有の上書きがあり、共通ルールとの優先順位や適用結果が変わり得る。
- 変更がコントラスト、視認性、状態表示、重なり合う装飾の判別に影響する。
- 既知のテーマ間差異や過去の不具合と関係する。
- 差分だけでは影響範囲を判断できない、またはテーマ依存がないと説明できない。

追加するテーマは、変更の影響を受けるテーマを根拠に選ぶ。テーマファイルを変更したという理由だけで無条件に3テーマすべてを必須にするわけではない。一方、影響するテーマを特定できない場合は、dark / silver / blue の3テーマすべてで確認する。

### 合成データでの検証

当面は **dark / silver / blue の3テーマすべて**で確認する。

この方針は暫定であり、実データでの検証範囲を dark 中心にできることを理由に、合成データのテーマ数も減らしてはならない。削減は別途、十分な実績と根拠を確認したうえで判断する。

## 毎回の実装チェックリスト

### 1. 差分と依存関係を確認する

- [ ] 変更差分（コード・CSS・トークン定義）を確認した。
- [ ] 対象要素に適用される共通CSSとテーマ別CSSを確認した。
- [ ] 参照している CSS カスタムプロパティの定義値、テーマ別上書き、継承関係を確認した。
- [ ] 既存の状態クラスや装飾と重なったときの影響を確認した。

### 2. 検証テーマを決める

- [ ] 実データでの実行時検証と、合成データでの検証を別々に判断した。
- [ ] 実データで dark のみとする場合、テーマ依存がないと判断した根拠を説明できる。
- [ ] テーマ依存がある場合、影響を受けるテーマを検証対象へ追加した。
- [ ] 影響範囲が不明な場合は検証範囲を広げた。
- [ ] 合成データを使う場合は3テーマすべてを対象にした。

### 3. 実機で確認する

- [ ] 対象機能を実データで操作し、期待する動作を確認した。
- [ ] 選択・hover・active・disabled など、変更に関係する状態を確認した（該当する場合）。
- [ ] 追加対象テーマでも同じ操作を行い、視認性・レイアウト・装飾の衝突を確認した。
- [ ] 合成データを使う場合、3テーマすべてで対象状態を確認した。

### 4. 結果を記録して完了する

- [ ] 確認したデータ種別（実データ／合成データ）を記録した。
- [ ] 確認したテーマを記録した。
- [ ] dark のみとした場合は、テーマ依存がないと判断した理由を記録した。
- [ ] 問題が見つかった場合は修正後に該当範囲を再確認した。
- [ ] 未確認のテーマや状態が残る場合は、検証完了と扱わず明示した。

| Phase85 | blue の `--diag-stroke` を視認性のため調整した。 | 線色などのテーマ別トークン変更は、影響テーマを確認する。 |

| Phase96–97 | 共通の状態表示と silver 専用 `.chart-measure--active` 上書きが干渉した。 | 共通CSSだけを見て判断せず、テーマ別上書きとの組み合わせを見る。 |

| Issue #150 | silver の `--color-green` に対応する RGB トークンがなく、共通の RGB 値を継承していたため、`--color-green-rgb` を追加した。 | 色トークンと RGB トークンの整合性、および alpha 合成時の見え方を確認する。 |

## 運用上の原則

- **ファイル名だけで決めない。** 差分、適用CSS、トークン定義、テーマ別上書きの関係から判断する。
- **dark のみは無条件の標準ではない。** テーマ非依存と説明できる変更に限る。
- **テーマ別ファイルの変更も、無条件に全テーマ必須とはしない。** 影響範囲を調べ、対象を根拠に基づいて選ぶ。
- **不確実性が残る場合は検証範囲を広げる。**
- **検証テーマの選択と、機能の動作確認を混同しない。** dark のみでよいと判断しても、必要な操作・状態の確認は省略しない。
- このガイドは Issue #132 の判断基準を正式ドキュメントへ反映したもの。運用実績に基づいて見直す場合は、本ガイドと Issue の両方を更新する。
